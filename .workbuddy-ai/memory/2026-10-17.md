### #1 网格方位角「60° 别名」bug（最隐蔽）

- **根因**：`process_image._survey_global_grid` 用 **2θ（模 180°）** 圆均值合成方位角，
  而等边三角形格点具有 **60° 旋转对称** → 7 个采样块 `[3,61,1,61,90,179,179]`
  被合成成 **21.2°**，而树心局部细扫的真值是 **59.0°（≡ −1.0°）**。
- **修法**：改为 **6θ（模 60°）圆统计**，并剔除偏离主方向 >15° 的对偶轴离群块（如 90°）。
  ⚠️ **禁止**"先 `angle % 60` 再取算术中位数" —— 真值卡在 0/60 边界时
  （−1°→59°、+1°→1°）会算出 **30°** 这种离谱值，必须用圆统计量。
- **验证**：`--grid-only` 实测 **0.67°**（日志："剔除 1 个对偶轴离群块 → 用 6/7 块合成 0.67°"），

### 金字塔：实测收益与真实代价（重要）

### 估算模块：真实数据验证抓出 3 个 bug（类型检查完全看不出来）

1. **网格索引 i 的范围必须逐 j 计算**（最严重）：格点沿行方向投影是
   `alongU = i*pitch + j*skew`，反解 `i = (du - j*skew)/pitch`；`j*skew` 在离原点
   较远的要素上可达 ±50 格位。用「全局 iMin/iMax」算死 → **远处要素一个格点都取不到**；
   实测症状：5,771 m² 连片空地得 0 株，全园排坑只有 286 株（应为 2,152）。
2. **经纬度→米不能用「1° ≈ 111320 m」常数**：纬度 1.18° 处子午圈每度只有
   **110,577 m**，用常数让面积系统性偏大 +0.67%（实测 TS 比 Python/UTM 大 0.75%）；
   改用大地测量曲率半径（M 子午圈 / N 卯酉圈）后误差降到 **0.09%**。
3. **必须按类别分口径**：`vacant_slot` 是"一个种植单元里少了 1 棵树"
   （实测 253 块 / 16,043 m² ≈ 63 m²/块）——网格法用 2 m 退让铺 8.45 m 间距格点会
   大量落空，面积法 `floor(63/66.67)` 又算成 0。两个口径都必须记 **1 株**，点位取质心。

### ⚠️ 但立刻暴露了一个真 bug（与沙箱无关）

打开截图能力后的第一张图是**纯色背景**（6,886 B / 唯一颜色 **1**）。
用 `--enable-logging=stderr --v=1` 抓 console 拿到根因：

```text
Uncaught Error: Style is not done loading.
The above error occurred in the <MapCanvas> component:
Consider adding an error boundary to your tree …
```

- **根因**：Terra Draw 的 MapLibre adapter 在 `start()` 时向地图注册自己的
  source / layer；此时 map style 尚未加载完 → 抛 `Style is not done loading.`。
  而它发生在 React 的 effect 里 —— **React 18 未捕获时会卸载整棵组件树**
  → 用户看到"整个界面消失"，而不是"地图坏掉"。
- **两处修法（缺一不可）**：
  1. Terra Draw 创建 + `start()` **移进 `map.on('load')` 回调**，并加 try/catch
     降级（绘制模块挂了只提示，不拖垮整页）；
  2. 每个区域包 **ErrorBoundary**（工具栏 / 图层面板 / 地图 / 属性面板 / 状态栏）。
- **修复验证（同页面同命令，只差这次改动）**：
  | 状态 | 体积 | 唯一颜色数 |
  |---|---|---|
  | 修复前 | 6,886 B | **1**（纯 #0f1417） |
  | 修复后 | **607,510 B** | **112,028** |
  分区核对：地图区 **109,675 色**、平均 RGB(35, 40, 26) —— **G 通道最高，即真实植被影像**。

### 有用的诊断手法（可复用）

1. **纯色截图 = 页面没渲染**：用 PIL 统计唯一颜色数，1 种即异常。

### ⚠️ 我算错过一个数学基准（外部纠正，已核实）

"树心到最近格点 P50 = 3.15 m，比随机基准 2.1 m 还差" —— **错了**。
2.1 m 是**一维**基准（d/4）；二维晶格随机基准是：

- 单株 Voronoi 面积 `A = 8.45 × 7.3179 = 61.836 m²`
- `P(≤r) = πr²/A` → `r₅₀ = √(A/2π) = 3.137 m`（实测 **3.15**，吻合 0.4%）
- `P(≤1m) = π/A = 5.08%`（实测 **5.1%**，分毫不差）

**即实测就是完美的二维均匀随机**，不是"更差"。教训：**给分布找基准前先确认维度**
（一维线段 vs 二维晶格的中位数差 1.5 倍）。
