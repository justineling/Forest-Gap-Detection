## 公司电脑「影像服务起不来」诊断（结论：不是打包问题）

### 关键事实（实测）
- 公司电脑装的包：`D:\Forest Gap Detection\py-runtime\desktop_entry\` **完整**——`_internal\` + `desktop_entry.exe`（15,187,358 B，时间 **10-19 15:42**），安装时间 10-20 14:24。
- 昨晚的修复 `73cf553` 是 **10-20 20:01** 提交 —— **晚于安装时间**，所以公司装的是没有该修复的旧包。
- 逐层实测（本机就是公司电脑）：
  1. `desktop_entry.exe --self-test` → `ok: true`，numpy 2.4.6 / rasterio 1.4.4 / shapely 2.2.0 / pyproj 3.7.2 / scipy 1.17.1，`proj_ok` `gdal_driver_ok` 均 true。
  2. 手动起服务（8799）→ `/meta` 200，47130×44686，`has_overviews: true`。
  3. **完全按外壳方式**（cwd=`%LOCALAPPDATA%\fgd\data`、默认 8765、`PYTHONUNBUFFERED/PYTHONIOENCODING/PYTHONUTF8`）→ 8765 LISTENING、`/meta` 200、无 traceback。
  4. `\\?\` 长路径前缀启动 → 同样 `ok: true`。
- ⇒ **exe、影像、依赖、打包、长路径都不是原因**。

### 诊断脚本的 bug（这次报告失去价值的原因）
`诊断影像服务.bat` 的安装目录输入**没清理引号/前导空格**：从资源管理器「复制为路径」粘贴会带 `"..."` → `if exist "!MANUAL!\py-runtime\..."` 必然失败 → 报"该目录下没有 desktop_entry.exe"（误报）→ 第 9/10 节（自检 + 直接起服务抓 traceback）被跳过。已修：`set MANUAL=!MANUAL:"=!` + `for /f` 去前导空格，四例实测正确。

### 我犯的误判（教训）
看到**本机** `desktop/runtime/desktop_entry/` 只有 `.gitkeep`，就断言"打包缺 PyInstaller → 包残缺"。实际上本机从没打过包，家里的包是完整的。**教训：判断"包是否完整"必须看安装目录/包内容，不能看开发机的构建目录。**

## 续：构建卡 22 分钟 + 8765 端口被占

### 「构建卡在 配置环境 40」真相
- `一键配置环境.bat` 开头有 `pause`，被 `构建安装包.bat` 自动调用时**没人按键** → 永久停在 "Press any key to continue"。
- 心跳（`_环境准备.bat` 的独立进程）仍在每 12 秒打印"仍在配置环境 40（已用 X 分 Y 秒）"，**误导用户以为在装环境**——实际向导一步都没跑。
- 修（提交 `1343835`）：3 处 pause 改 `if not defined FGD_NO_PAUSE pause`，`_环境准备.bat` 调用前设 `FGD_NO_PAUSE=1`。
  ⚠️ 不能用参数传：`一键配置环境.bat` 把 `%*` 原样转给 ps1，而 cmd 的 `shift` **不影响 `%*`**。
- 同时：英文入口不再调用中文向导，改走新增 `:ensure_env_en`（rustup default stable / venv+pip / npm，命令本身英文输出）→ 实现"中文入口全中文、英文入口全英文"。

### 8765 端口被占（新包 `73cf553` 已给出准确诊断）
- 新包报："端口 8765 被其它程序占用 —— 探活结果：应答不是合法 HTTP"，子进程存活，服务日志空。
- 应用日志出现 `[tile_server] ====` + "瓦片服务已退出：退出码 1（0x00000001）" —— 服务 bind 失败或启动即退。
- 但**诊断时刻 8765 无 LISTENING**（只有服务自己留下的 TIME_WAIT），现在（09:35）8765 完全空闲。
- 【10】8799 起服务：`PROC_STILL_RUNNING` + `META_OK` → **服务本身完全正常**。
- ⇒ 公司电脑上有**间歇性占用 8765 的非 HTTP 服务**；需在应用运行时执行
  `Get-NetTCPConnection -LocalPort 8765 -State Listen | Select-Object OwningProcess` 定位。
- 待办（未做）：应用支持**端口回退**（8765→8766…，前端从事件取实际端口），根治"端口被占"。
