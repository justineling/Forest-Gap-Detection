## 公司电脑「影像服务起不来」诊断（结论：不是打包问题）

### 关键事实（实测）
- 公司电脑装的包：`D:\Forest Gap Detection\py-runtime\desktop_entry\` **完整**——`_internal\` + `desktop_entry.exe`（15,187,358 B，时间 **10-19 15:42**），安装时间 10-20 14:24。
- 昨晚的修复 `73cf553` 是 **10-20 20:01** 提交 —— **晚于安装时间**，所以公司装的是没有该修复的旧包。
- 逐层实测（本机就是公司电脑）：
  1. `desktop_entry.exe --self-test` → `ok: true`，numpy 2.4.6 / rasterio 1.4.4 / shapely 2.2.0 / pyproj 3.7.2 / scipy 1.17.1，`proj_ok` `gdal_driver_ok` 均 true。

- ⇒ **exe、影像、依赖、打包、长路径都不是原因**。

### 诊断脚本的 bug（这次报告失去价值的原因）
`诊断影像服务.bat` 的安装目录输入**没清理引号/前导空格**：从资源管理器「复制为路径」粘贴会带 `"..."` → `if exist "!MANUAL!\py-runtime\..."` 必然失败 → 报"该目录下没有 desktop_entry.exe"（误报）→ 第 9/10 节（自检 + 直接起服务抓 traceback）被跳过。已修：`set MANUAL=!MANUAL:"=!` + `for /f` 去前导空格，四例实测正确。

### 我犯的误判（教训）
看到**本机** `desktop/runtime/desktop_entry/` 只有 `.gitkeep`，就断言"打包缺 PyInstaller → 包残缺"。实际上本机从没打过包，家里的包是完整的。**教训：判断"包是否完整"必须看安装目录/包内容，不能看开发机的构建目录。**

### 8765 端口被占（新包 `73cf553` 已给出准确诊断）
- 新包报："端口 8765 被其它程序占用 —— 探活结果：应答不是合法 HTTP"，子进程存活，服务日志空。

  `Get-NetTCPConnection -LocalPort 8765 -State Listen | Select-Object OwningProcess` 定位。

## 续 2：向导格式化刷屏 + MSVC 缺失（本机无法打包）

### 下载进度格式化刷屏（已修 `e496d5c`）
- 症状：阶段 4 刷屏 `Error formatting a string: Index (zero based) must be ...`
  at `配置环境.ps1:219`。
- 根因：`[Console]::Write("..." -f $mb, $el)` —— **方法调用参数列表里的逗号是参数分隔符**，
  `-f` 只拿到 `$mb`，字符串里的 `{1}/{2}/{3}` 越界。两处（有/无 ExpectedBytes 分支）都中招。
- 修：先算整行再 `Write`。ps1 语法解析 0 错误，格式化输出正常。

### MSVC 缺失 = 本机无法打包（关键环境事实）
- 本机（公司 54BJ862）：`[警告] MSVC C++ 生成工具：未找到`，Rust 曾无默认工具链。
- 向导原提示"改用 GNU 工具链（免管理员，可正常构建）"是**错的**：Tauri v2 在 Windows
  只支持 MSVC（WebView2 loader 要链 .svc/.lib），GNU 能编普通 Rust 但 `tauri build` 必失败。
  已改为明确提示 + 恢复 `Add-Manual`（VS 2022 生成工具，勾「使用 C++ 的桌面开发」，需管理员 2~6 GB）。
- `check_runtime` 新增 MSVC 检测（**只用 vswhere**；`where link` 会被 MSYS 的
  `/usr/bin/link` 误判成已装），阶段 1 即警告，不阻断。
- ⇒ **这台机器要打包必须先装 VS 2022 Build Tools**；否则只能回家里打包。

## 续 4：Rust 工具链损坏（cargo 能跑、rustc 不能）

- 现象：`[已就绪] Rust 工具链` + `[已就绪] MSVC`，但 `tauri build` 在
  `crates/tauri-cli/src/interface/rust.rs:1145` **panic**，报错完全指不到 Rust。
- 实测根因：`cargo --version` → `cargo 1.99.1`（能跑），但
  `rustc --version` → `error: missing manifest in toolchain 'stable-x86_64-pc-windows-msvc'`
  （安装被中断）。`cargo metadata` 也能跑（不调 rustc），所以 tauri-cli 卡在后续步骤。
- 误判澄清：MSVC 其实**可用**——vswhere 报 `Visual Studio 2019 Professional`，
  `VC/Tools/MSVC/14.29.30133/bin/Hostx64/x64/link.exe` 存在。用户以为"没装 C++ 桌面开发"。
- 修法（三处）：
  1. `check_runtime`：Rust 判定改为 `cargo --version` **且** `rustc --version` 都通过。
  2. `ensure_env_en`：rustc 失败 → 走 `:en_rust_repair`（`rustup toolchain install stable`
     + `rustup default stable` + 双重复核；仍失败则给两条手动命令）。
  3. `配置环境.ps1`：修复从 `rustup default stable` 改为先 `rustup toolchain install stable`
     再 default（default 只设默认，不补文件）；检测文案改为"工具链不完整"。
- 兜底提示：两个入口的 `:build_fail` 增加识别——报错含 `panicked at` + `rust.rs` /
  `missing manifest` → 提示 `rustup toolchain install stable`。
- 本机修复执行中：`rustup toolchain install stable`（约 300 MB）。
