## 下午：关窗拦截（`29bf1f5`）

- 需求：检测中关窗要提示；执意关闭要保证无负面影响；顺带问"当前是关 UI 还是真退出"。
- **当前项目没有系统托盘** → 点 × = **真退出**（不是隐藏后台）。
  `RunEvent::Exit` 清理：tile kill / detect kill+wait / overviews kill+wait /
  **derive 刻意不杀**（正在写 CHM，跑完比留半个好）。
- 实现：`lib.rs` 加 `.on_window_event` → `CloseRequested` 时查 detect/derive；
  在跑就 `api.prevent_close()` + **系统原生 dialog**（不用前端弹框：此时前端可能
  已在卸载，自定义弹框会闪一下就没）。
  - 「继续等待（不关闭）」→ 什么都不做
  - 「中断并退出」→ kill detect（derive 保留）→ `app.exit(0)` → 走正常清理
- 中断安全性依据：`process_image.py` 的输出是**原子写入**（先写 `.tmp` 再
  `os.replace`），所以中断不会留损坏 JSON，只会留无害 `.tmp`。
- 验证：`cargo check` 1m09s 零 error。
- 结论：**不做系统托盘**。检测是一次性任务（3~6 分钟）不是常驻服务，
  托盘会制造"以为关了其实还在跑"的困惑；保持 × = 退出 + 检测中确认最符合预期。
