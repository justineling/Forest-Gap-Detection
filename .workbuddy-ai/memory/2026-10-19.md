### 2.2 判断：问题不是按钮多，是没有状态

界面不知道用户走到哪一步 → 把全部可能性同时摊开 → 用户自己判断。
商用软件不该这样。

### 2.3 做法

`lib/workflow.ts` 纯函数（45 项单测）算五步状态 + `nextAction()`；
`StepRail` 进度条（done 可点 / active 高亮 / todo 禁用）；
`NextStepCard` 右下角浮动卡片（1 主 + ≤2 次，走完自动换内容，可折叠成胶囊）；
`MoreMenu` 收纳低频（换数据 / 参数 / 补画 / 估算 / 快捷键 / 日志）。

header 最终：品牌 + 五步进度条 + 影像灯 + ↶ ↷ + ⋯。

### 2.4 两个语义陷阱（测试抓出来的）

1. **「可选」≠「不阻塞」**：② 范围可选且不阻塞（跑整幅常见）；
   ④ 复核可选**但阻塞**（最该被引导，跳过靠点主按钮）。
   合成一个 `optional` 字段 → 有结果时第 4 步永远不亮。
2. **「当前有要素」≠「载入过结果」**：用户删光误报后 `gaps.length===0`，
   用它会判断第 3 步未完成 → 流程倒退、要求重跑。

## 三、用户报障：检测完「没有空地」——根因是路径不匹配（10-19 上午）

### 3.1 现象

用户在桌面端跟五步流程走，第 3 步检测跑完，界面显示没有空地。

### 3.2 实测证据（先查产物，别猜）

- 产物**存在且正常**：`%LOCALAPPDATA%\fgd\data\output\wgr17-desktop-gaps.geojson`
  1,762 要素（open_patch 420 + vacant_slot 342 = **762 块确定需补种**），14.5 MB。
- `processing.tiles_processed=283 / 528` **不是中断** —— 283 是"需要处理的瓦片数"
  （其余是影像外空白，与"园区占外接矩形 57%"吻合）。别被这个数字误导。
- 用独立端口起 tile_server 显式 `--gaps` 指向该文件 → `/gaps` 立刻返回 1,762 要素，
  `planting_grid` 锚点也正常。**证明文件没坏，问题在读的一侧。**

### 3.3 根因链（三方路径互不相认）

| 环节 | 它认为结果在哪 |
|---|---|
| sidecar 写 | `output/{job}-gaps.geojson`，job=`wgr17-desktop` → `wgr17-desktop-gaps.geojson` |
| Rust `resolve_gaps()` | **只认** `wgr17-final-gaps.geojson` / `wgr17-elev-gaps.geojson`（写死）→ 找不到 → 不传 `--gaps` |
| `tile_server.GAPS_CANDIDATES` | 同样写死三个名字，且基于 `ROOT=Path(__file__).parent.parent`；**打包态 ROOT 指向 `py-runtime/desktop_entry/`，那里没有 output/** → 全 miss → `gaps_path=None` |
| `/gaps` | 返回 `{features: [], error: "未找到检测结果文件"}` |
| 前端 `normalizeCollection` | **把 error 丢了** → 用户只看到"0 块" |

### 3.4 临时解法（已执行）

1. `cp wgr17-desktop-gaps.geojson wgr17-final-gaps.geojson`（同目录）→ 重启软件即能看到。
2. 补齐打包数据目录：`output/chm.tif`（60 MB）+ `output/forest-mask-50m-exg60.geojson`。
   之前 `data/output/` 只有检测产物 → CHM 缺失 → 退化纯 RGB：实测 **water 只有 2 块**
   （基线 21 块）、**undeveloped 0 块**（基线 25 块），即水体漏检 + 未开发林未剔除。

### 3.5 待修（BugFix 团队 `software-fgd-gaps-empty` 进行中）

A. Rust `resolve_gaps` 改"扫描 output/*gaps*.geojson 取 mtime 最新"+ 单测
