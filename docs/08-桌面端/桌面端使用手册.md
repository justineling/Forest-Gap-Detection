# 桌面端使用手册

> 给**最终用户 / 现场作业员**看。不讲原理，只讲怎么点。
> 想知道"为什么这么设计"，看同目录的 `桌面端实现说明.html`。

---

## 0. 这是什么

一个装在 Windows 上的桌面软件：给它一张油棕园的航拍图，它告诉你**哪几块地该补种、补多少棵、每棵种在哪**，
最后给你一沓文件，现场拿着就能干活。

**它不需要你装 Python、不需要装 GIS 软件** —— 安装包里已经带了全部运行时。

---

## 1. 安装

双击 `Forest Gap Detection_x.y.z_x64-setup.exe`，一路下一步。

- 默认装到 `%LOCALAPPDATA%\Forest Gap Detection`（不需要管理员权限）
- 装完从「开始菜单」或桌面快捷方式启动
- 首次启动会在 `%LOCALAPPDATA%\fgd\data` 建一个数据目录

> **卸载**：用安装目录里的 `uninstall.exe` 或「设置 → 应用」。
> ⚠️ **不要手动删安装目录** —— 卸载记录和磁盘对不上，下次装会弹 `Unable to install`。

---

## 2. 第一次打开：选两个文件

首次启动会弹一张卡片，只做两件事：

| 步骤 | 选什么 | 说明 |
|---|---|---|
| ① | **正射影像**（`.tif` / `.tiff`） | 必填。就是那张几 GB 的航拍图 |
| ② | **检测结果**（`.geojson`） | 可选。有历史结果就选，没有就跳过 |

点「开始使用 →」，软件会记住路径，**下次打开直接用**。

> 想换数据：点右上角**「⋯ 更多 → 更换影像或结果文件」**，会重新弹出这张卡片。

**关于配套文件**：如果你把一整套数据（航拍图 + `chm.tif` + `segment.tif` + `forest-mask*.geojson`）
放在同一个文件夹里，软件会**自动去那儿找**，不用一个个指定。

---

## 3. 干活：跟着「下一步」走

整个软件就是一个**五步流程**。任何时刻，只有一处告诉你现在该做什么 ——
**地图右下角那张卡片**。它的按钮就是下一步，做完自动换成下一条。

```
① 选择影像 → ② 确定范围 → ③ 运行检测 → ④ 复核结果 → ⑤ 导出交付
```

顶部那排是进度，不是按钮墙：

| 长相 | 含义 |
|---|---|
| **绿色勾** | 这步做完了（可以点回去重看 / 重做） |
| **高亮发光** | 你现在在这步 |
| **灰色数字** | 还没到，点不动是正常的 |

卡片的三个用法：

- **点主按钮** = 往前走
- **点次按钮** = 走另一条路（比如「手绘范围」或「导入 KML」）
- **点右上角 `⌄`** = 收起成小胶囊，不挡地图；进入下一步会自动再展开

> 如果你把卡片收起了、又忘了该干什么：看顶部高亮的是第几步，
> 或者点一下右下角那个胶囊。

### ① 选择影像

第一次打开时软件就自动弹卡片让你选，不用找按钮。

选两样东西：**正射影像**（`.tif`）和**检测结果**（`.geojson`）。
选过一次就记住了，以后打开直接用。

> 想换数据：点右上角「⋯ 更多 → 更换影像或结果文件」。

### ② 确定范围（可选，但强烈建议）

卡片会给两个次按钮，任选其一：

- **手绘范围**：在地图上依次点几个顶点 → 双击闭合
- **导入 KML**：选 `.kml` 或 `.geojson`（奥维、Google Earth 都能导出）

导入后地图会**自动飞到那个位置**，让你确认框住了哪片地。

> **为什么建议圈**：不圈就跑整幅，6 分钟；圈了只跑圈内，**3 分钟**。
> 而且圈外的天然林、邻居家的园子从一开始就被排除，不会再来捣乱。

### ③ 运行检测

点卡片上的「开始检测」。

**第一次会先"体检"**（一秒）：

- 全绿 → 直接开跑，不打扰你
- 有问题 → 弹一张卡片，逐项说清"缺什么 / 会有什么后果"
  - 红色 = 必须解决（点「去选择数据」）
  - 黄色 = 会影响结果但能跑（点「仍然开始」自己担着）

跑起来后顶部有一条进度带：

```
检测中 24% ｜ 128 / 528 块 ｜ 已用 1 分 25 秒 ｜ 预计剩余 4 分 24 秒 ｜ 已发现 312 块空地
```

想中止就点右边的「取消」—— 子进程会被杀掉，不会留后台。

跑完变成绿色的「✓ 检测完成 · 1,443 块 · 用时 5 分 50 秒」，结果**自动载入**，
卡片自动跳到「复核结果」。

### ④ 复核结果

见第 4 节。看完点卡片的「复核完成，去导出」；不改直接导出也可以。

### ⑤ 导出交付

点卡片上的「导出交付包」，见第 5 节。

> **顺便估算株数**：想看每个补种点位在哪，点「⋯ 更多 → 估算可种植数量」。

## 4. 复核：把算法的错误改掉

这一步决定交付质量。1,726 块里通常有几百块需要人看一眼。

### 4.1 复核清单（右面板「复核」标签）

默认打开就是这个标签，**按面积从大到小排** —— 前 30 个大块通常占 80% 的争议面积。

- 筛选：`全部` / `待复核` / `已改过` / `人工新增`
- 最小面积：`不限` / `≥100` / `≥500` / `≥1000`
- **点任意一行** → 地图飞过去并高亮（如果该类别是隐藏的，会自动帮你打开）

### 4.2 三种改法

| 想做什么 | 怎么做 |
|---|---|
| **改类别**（这块其实是道路） | 选中 → 右侧「属性」里改下拉框 |
| **删除**（这块是误报） | 选中 → 按 `Delete`，或点属性面板的「删除此多边形」 |
| **补画**（算法漏了） | 点「⋯ 更多 → 手工补画一块空地」→ 在地图上画 |

### 4.3 批量处理（一片都是误报时）

1. 点卡片上的「框选多选」（或「⋯ 更多 → 框选多选」）→ 在地图上拖一个方框
2. 底部出现批量栏：`已选 12 块 · 合计 3,420 m² · 连片空地 8 · 不确定 4`
3. 选好目标类别 → 点「应用改判」；或直接点「删除」

> **重要**：框选**只认你左侧勾了勾的类别**。
> 道路、水体这些默认是隐藏的，就算框到了也不会被选中 —— 防止误删看不见的东西。

### 4.4 改错了怎么办

**`Ctrl + Z` 撤回**，`Ctrl + Y` 重做。

- **一次批量操作 = 一次撤回**：框选删 40 块，按一次 `Ctrl+Z` 全部回来
- 最多能撤 40 步
- 拖拐点时，一次拖动只算一步（不会把额度用光）

右上角的 `↶ 3` `↷ 1` 显示还能撤/重做几步。

### 4.5 快捷键

| 键 | 作用 |
|---|---|
| `Ctrl + Z` | 撤回 |
| `Ctrl + Y` / `Ctrl + Shift + Z` | 重做 |
| `Delete` / `Backspace` | 删除选中（可多选） |
| `Esc` | 退出当前模式 / 取消选择 |
| `Shift` 或 `Ctrl` + 点击 | 加选 / 减选 |

> 光标在输入框里时，这些快捷键**全部让位**给输入框（不会误删多边形）。

### 4.6 换园区：先「生成高度图与林地边界」

⚠️ **换园区、换航拍批次时必须做这一步。** 不做的话检测会退化成"只看颜色"：
水塘只能认出 2 块（本该 21 块）、未开发林一块都剔不掉。

入口：**「⋯ 更多 → 生成高度图与林地边界…」**

它对两件事：

| 生成什么 | 从哪来 | 干什么用 |
|---|---|---|
| **高度图** `chm.tif` | 用 `dsm.tif` 减去地面高程 | 判断"多高才算树" |
| **林地边界** `forest-mask.geojson` | 高度图 + 树心表 | 标出未开发的天然林，别算成可补种 |

它检查什么（缺了会拦你，不会让你白等）：

- **正射影像**（必需：高度图要按它的网格对齐）
- **`dsm.tif`**（必需：这是唯一真正必需的输入）
- `segment.tif`（可选：缺了水面不会被置空，水塘可能算出偏高的树高）
- `tree_info.json`（可选：缺了只生成高度图，林地边界会跳过）

耗时约 **1 分钟**（本项目实测 42 秒）。生成时会覆盖同名的 `chm.tif` /
`forest-mask.geojson`，界面会先提醒你。

> **⚠️ 生成完必须重跑一次检测。** 旧结果是拿旧的高度图算的，
> 直接导出会得到和新高度图对不上的数字 —— 而界面上看不出任何异常。
>
> 忘了重跑也没关系：软件会在状态栏顶部显示一条橙色的「结果可能已过期」，
> 点它不用管，但**别忽略** —— 那意味着屏幕上的数字不是按当前高度图算的。
>
> 如果检测前的"体检"提示缺高度图/林地边界，那张卡片上也会直接给
> 「去生成高度图 / 林地边界」按钮，不用自己去菜单里找。

### 4.7 🎯 验证集：量出「算法到底有多准」

复核是**改错**，验证集是**测量**。两者目的不同，所以入口分开：

> 右面板「复核」标签 → 顶部切换成 **`🎯 验证集`**

#### 它是什么

软件从 1,726 块里**分层抽 150 块**给你判真值（是不是真的该补种）：

| 层 | 抽几块 | 为什么抽它 |
|---|---|---|
| L1 大块（≥500 m²） | 40 | 面积占大头，判错代价最大 |
| L2 不确定块 | 60 | 算法自己没把握的，最能暴露问题 |
| L3 可补种 | 25 | 检查"确定需补种"的纯度 |
| L3 林间空隙 | 15 | 检查有没有该补的漏了 |
| L3 不可种植 | 10 | 检查道路/水体有没有误判 |

抽完后每块带一个**权重**（逆概率权重：抽中概率越小，代表越多块）。
把 150 块判完，就能反推**全园**的准确率——不用把 1,726 块全判一遍。

#### 怎么判（全键盘，不用鼠标）

| 键 | 作用 |
|---|---|
| `↑` / `↓` | 上一条 / 下一条（地图自动飞过去） |
| `1` | 判「真该补种」（算法对） |
| `2` | 判「其实不该补种」（算法错——它是树/硬化地面） |
| `3` | 判「真值也说不清」（跳过，不计入准确率） |
| `4` | 判「算法漏了，但这块确实该补」（用于 L3 层） |
| `Space` | 确认当前这条的判定并自动跳下一条 |

判完一条会自动跳到下一条，所以是「看一眼 → 敲个数字 → 下一条」的节奏。
150 块熟练后约 **20~30 分钟**。

> **⚠️ `L2 不确定块`不能"直接确认"**：算法本来就标的是"不确定"，
> 你必须按 `1/2/3` 给一个真值。按 `Space` 会提示"请按 1/2/3 选一个真值"。
> （早期版本允许直接确认，结果 60 块里 51 块存成了"存疑"，这一层等于没做。）

#### 进度不会丢

每判一块就写进浏览器本地存储，**关掉软件、重启电脑都还在**。
列表顶部显示 `已判 87 / 130`（130 = 150 减去随机抽中但已被人工删掉的块）。

想重来：切到别的范围 / 点「重新抽样」（会明确二次确认，因为会清空进度）。

#### 判完怎么办

点 **「导出标注 JSON」** → 得到 `validation-{时间}.json`，然后跑评估脚本：

```bash
.venv/Scripts/python.exe scripts/eval_validation.py 你的标注.json
```

会打印三档准确率：

| 指标 | 含义 | 什么时候看 |
|---|---|---|
| **样本准确率** | 150 块里判对多少 | 想知道自己判得累不累 |
| **★ 全园无偏准确率** | 加权反推全园 | **对外报数用这个** |
| **面积加权准确率** | 按面积加权 | 想知道"错在不在大块上" |

外加混淆矩阵（哪类错判成哪类）、分层小表（哪一层最差）、
以及「确定需补种」的 precision / recall。

> **一次判、多次用**：同一份标注可以喂给不同版本的算法结果做对比：
> ```bash
> .venv/Scripts/python.exe scripts/eval_validation.py 标注.json 旧结果.geojson 新结果.geojson
> ```
> 但脚本会警告：**两个版本差距 < 2 个百分点时视为不可区分** ——
> 150 块的抽样误差就有这么大，别把噪声当改进。

#### 分不清「不补」和「不可种」怎么办

这两个选项确实容易混：

| 选项 | 意思 | 例子 |
|---|---|---|
| `2 无需补种` | 这块**空着但不该补** | 两行树之间的通行道、树冠遮住的小缝 |
| `3 不可种植` | 这块**压根不能种** | 水泥路、水塘、工棚、天然林 |

从"要不要派人去挖坑"的角度看，这两个的答案是一样的 —— **都不用挖**。
所以如果你在图上分不清，**可以统一按 `3` 标**，然后评估时加一个开关：

```bash
.venv/Scripts/python.exe scripts/eval_validation.py 你的标注.json 结果.geojson --merge-not-plant
```

它会：
- 把真值的 2 和 3 合并成「不补」，算法的"林间空隙"和"道路/水体/办公区"也合并成「不补」
- **把"待复核"的块排除出计分**（算法说"要人看"不是一个判断，记对记错都是冤枉它）
- 单独打印一行「合并口径」的准确率，并给出「补 / 不补」的混淆矩阵

此时评估回答的是 **「这块该不该补」** 这个业务问题，而不是四分类。
不加这个开关时，脚本的输出与以前**完全一致**。

> 第一次用真实标注跑（150 块、只有 1 和 3）：
> 严格口径 44.7% / 39.6%，合并口径 **88.9% / 77.9%**。
> 差的这一大截不是算法的问题，是口径没对齐 ——
> 算法的"林间空隙"被标成了"不可种植"，严格口径下全算错。

## 5. 导出交付包

点卡片上的「导出交付包」：

1. **选输出目录**（记住上次选择；浏览器里可以直接手填路径）
2. 确认摘要：要素数 / 退让距离 / 人工痕迹 / 范围
3. 点「开始导出」
4. 完成后列出全部文件，点 **「📂 打开文件夹」** 直接去拷走

### 5.1 交付包里有什么（21 个文件）

| 文件 | 给谁用 |
|---|---|
| `gaps-all-wgs84.geojson` | GIS 通用格式 |
| `gaps-all-utm49n.geojson` | 现场量算（单位是米） |
| `gaps-all-wgs84-shp.zip` | **ArcGIS** 拖进去就能出图 |
| `gaps-all-utm49n-shp.zip` | 同上，投影坐标版 |
| `gaps-all.kml` | **奥维 / Google Earth** 打开 |
| `by-class/*.zip`（8 个） | 按类别分开的单层文件 |
| `planting-points-wgs84.geojson` | 补种点位 |
| `planting-points-utm49n.geojson` | 同上，米制 |
| `planting-points-wgs84-shp.zip` | 点位 Shapefile |
| `planting-points-utm49n-shp.zip` | 同上 |
| `planting-points.kml` | 点位 KML（手机导航到每个坑位） |
| `planting-points.csv` | **手持 GPS 放样**（一行一个点） |
| `gaps-edited.csv` | 业务方直接看的表格 |
| `补种勘察一页报告.html` | **给主管签字**，`Ctrl+P` 存 PDF |

> **关键**：这些文件里是**你复核之后**的结果。改判、剔除、补画全都在里面。

### 5.2 一页报告

双击打开 `补种勘察一页报告.html`，浏览器里 `Ctrl + P` 就能打印或存成 PDF。

五块内容：参数卡片 → 三档口径（含图表）→ 要买多少苗 → 你改了多少 → 最大的 20 块。

## 6. 出问题了看哪里

### 6.1 先看日志

```
%LOCALAPPDATA%\fgd\logs\app.log
```

这里会写清楚：用的是打包运行时还是开发环境、数据根在哪、瓦片服务起来没有。
**报问题的时候把最后 20 行贴出来，基本就能定位。**

### 6.2 常见症状

| 症状 | 原因 | 怎么办 |
|---|---|---|
| 地图一片黑，顶部状态灯是红的 | 没选影像，或服务还没起来 | 点「⋯ 更多 → 更换影像」；已选过就等 10 秒（首次要建索引） |
| 弹「还差一点，检测没法开始」 | 缺关键文件 | 按卡片提示补文件，或点「去选择数据」 |
| 弹「这几项会让结果不准」 | 缺 CHM / 分割 / 森林掩膜 | 看黄色项说的后果，能接受就「仍然开始」 |
| **状态栏顶部出现橙色「结果可能已过期」** | 高度图 / 分割图在检测之后被换过（比如刚点了「生成高度图」但没重跑检测） | 重新跑一次检测。旧结果是按旧的高度图算的，直接导出会得到对不上的数字 |
| **检测跑完，界面却是「没有空地」** | 结果文件没找到（检测可能成功了，只是写在了别的目录） | 看右下角卡片写的「已查找：…」，把文件放到那个目录；或点「⋯ 更多 → 更换影像或结果文件」指一下 |
| 检测跑完但结果明显偏少 | 大概率缺 CHM（退化成只看颜色） | 看日志里有没有 `W1004`；用「⋯ 更多 → 生成高度图与林地边界」补上 |
| 生成时报"没找到 dsm.tif" | 大疆导出目录里没有这个文件，或放错位置 | 把 `dsm.tif` 放到影像同目录（它就是大疆的"地表高程"） |
| 水体/未开发林明显没被识别 | 数据目录缺 `chm.tif` 或 `forest-mask*.geojson` | 把这两个文件放进 `%LOCALAPPDATA%\fgd\data\output\`，重新检测 |
| 导入 KML 提示「请先解压」 | 选的是 `.kmz`（压缩包） | 解压出 `.kml` 再导入 |
| 导入提示「这看起来是投影坐标」 | KML 里是 UTM 米，不是经纬度 | 在奥维/GE 里导出成 WGS84 经纬度 |
| 导出后文件夹是空的 | 输出目录没写权限 | 换一个目录（别选 `C:\Program Files`） |
| 装的时候弹 `Unable to install` | 上次是手动删的安装目录 | 用 `uninstall.exe` 卸干净再装 |

### 6.3 性能参考

| 场景 | 耗时（8 核机器） |
|---|---|
| 全量 528 瓦片 | **约 6 分钟** |
| ROI 121 瓦片 | **约 3 分钟** |
| 打开影像（首次建索引） | 10~20 秒 |

> 机器内存建议 **8 GB 以上**。并行进程数可在「⋯ 更多 → 检测参数」里调：
> 1（串行，最稳）/ 2（低配）/ 4（默认）/ 6（最快）。

### 6.4 换园区 / 换树龄：记得改「林龄档位」

「⋯ 更多 → 检测参数」里第一项是**林龄档位**，它决定"多高才算树"：

| 档位 | 适用 | 救援线 / 否决线 |
|---|---|---|
| **成熟林**（默认） | 8~15 m 的成树 | 5.2 m / 1.2 m |
| 中龄林 | 约 4~7 年生 | 3.5 m / 0.8 m |
| 幼龄林 | 约 2~4 年生 | 2.2 m / 0.5 m |

**为什么重要**：算法靠"高度"判断一棵树在不在。但大疆的高程数据会把树高
**低估约 40%**，而默认的 5.2 m 是在**成熟园区**标出来的。
如果你换到幼龄林还用默认档，那些 2~4 m 高的小树会被当成"空地"，报出一堆不该补的地。

> ⚠️ 选幼龄林档时，界面会提示"幼树与高草高度接近，建议配合复核清单抽查"。
> 这不是客套话 —— 2~4 m 的幼树和 1.5 m 的高草，在单张照片上确实难分。
>
> ⚠️ 改档位会让**已算好的瓦片失效**，需要重跑（全量约 6 分钟）。界面会提示。
> 导出的报告里会写明本次用的档位；**非默认档位会标黄**，提醒不可与历史数字直接比。

## 7. 几条要记住的

1. **卸载走 `uninstall.exe`**，别手删目录
2. **圈了范围再检测**，快一倍且更干净
3. **框选前先确认左侧勾了哪些类别** —— 只有勾了的才会被选中
4. **交付前一定过一遍复核清单**，尤其是面积最大的那 20 块
5. **不确定下一步做什么就看右下角卡片** —— 它永远只说一件事
6. 报问题时附上 `app.log` 的最后 20 行（`⋯ 更多 → 打开输出目录`，日志在 `%LOCALAPPDATA%\fgd\logs`）
