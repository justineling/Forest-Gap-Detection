# 五步流转与弹窗语义

> 这份文档回答两个问题：**「我现在在第几步、怎么前进、怎么退回去」** 和
> **「我点了 ×，到底改变了什么」**。
>
> 权威实现只有一处：`desktop/src/lib/workflow.ts`（纯函数，有单测）。
> 本文是它的**人话版本** —— 如果你改了 `isStepDone` 或某个弹窗的取消分支，
> 请同步改这里，否则下次又会有人拿文档当依据来问"为什么和说好的不一样"。

---

## 一、五步总表

`active`（当前步骤）的判定规则只有一句：**第一个"参与流程且未完成"的步骤**；
例外是检测进行中时强制停在第 3 步（`computeSteps` 里的 `detectRunning` 分支）。

| # | 步骤 | 进入条件 | 完成条件（`isStepDone`） | 能回退到哪 / 怎么回退 |
|---|------|----------|--------------------------|------------------------|
| ① | 选择影像 | 无条件（启动即是） | `hasImage`：影像服务就绪（`.tif` 已选中且瓦片服务应答 `/meta`） | 无更早的步骤。可以**重做**：步进器点① / 工具栏「⋯ 更多 → 更换影像或结果文件」/ 卡片「选择正射影像」/ 启动弹窗「换一张影像」→ 都打开同一个向导 |
| ② | 确定范围 | ① 已完成 | `hasRoi`（圈选或导入 KML）**或** `detected`（本次跑过检测）**或** `hasResult`（磁盘上有结果） | 第 3 步的次按钮「清除圈选，改跑整幅」→ `setRoi(null)` → ② 重新成为 active，三个入口（圈定范围 / 导入 KML / 跳过跑整幅）全部回来 |
| ③ | 运行检测 | ① ② 已完成 | `detected` **或** `hasResult` | ① 结果弹窗「重新开始」→ `setGaps([])` + `setRoi(null)`；② 向导提交后走 B2 分支 → `setGaps([])` + `setRoi(null)`（两处一致，见 4.1） |
| ④ | 复核结果 | ① ② ③ 已完成 | `reviewed`（点过「复核完成」）**或** `edited`（有过人工增删改）**或** `exported` | 卡片「重新检测」（**只在结果被删空、`gapCount === 0` 时出现**）；否则要重跑只能从①②的入口重来一次 |
| ⑤ | 导出交付 | ① ② ③ ④ 已完成 | `exported` —— 由导出**成功**的回调置位（`ExportDialog.run()` 在 `out.ok !== false` 之后 `markWorkflow({ exported: true })`；失败/取消不置位） | 无回退 —— 导出是终点。可以再导一次（覆盖上一次的输出目录） |

### 两个容易误解的点

1. **第 ② 步标着「可选」，但它参与 active 计算**（`blocks: true`）。
   之所以不会把人卡死，是因为它的完成条件很宽：跑过检测也算完成。
   反过来，早先把它设成 `blocks: false` 时，用户选完影像界面直接跳到第 3 步，
   "可以先圈范围"这个功能就**入口消失了**。
2. **`hasGaps` 与 `hasResult` 不是一回事**。用户把误报全删光后 `hasGaps` 变 false，
   但 `hasResult` 仍为 true —— 否则流程会倒退成"你还没跑检测"，等于告诉他数据丢了。

## 二、逐步的"出口"清单

| 步骤 | 主动作 | 其它出口 |
|------|--------|----------|
| ① | 向导里选 `.tif` → 「开始使用」 | 取消（× / Esc / 点遮罩）= **什么都不变** |
| ② | 卡片主按钮「圈定范围」（`drawRoi`） | 次按钮「导入 KML」/「跳过，跑整幅」 |
| ③ | 卡片主按钮「开始检测」（先开参数窗确认） | ① 参数窗里「开始检测」→ 预检 → 真正开跑；② 步进器点第 ③ 步也直接进参数窗（带「开始检测」按钮，见 4.3） |
| ④ | 卡片主按钮「复核完成，去导出」（记 `reviewed` + 直接开导出窗） | 任何人工编辑自动算完成；直接导出也算 |
| ⑤ | 卡片主按钮「导出交付包」→ 导出窗「开始导出」 | 导出成功后卡片自己变成「打开输出文件夹」（`finished: true`） |

## 三、弹窗 / 浮层的取消语义总表

**判据**：取消之后，用户的数据、界面状态、步骤位置有没有变化？
"非破坏性" = 一个字节都不变。

| 弹窗 | 关闭方式 | 语义 | 破坏性 |
|------|----------|------|--------|
| `ResumeDialog`（发现上次的检测结果） | `×` / `Esc` / 点遮罩 | **= 继续复核**（应用暂存的那份结果，只关窗）。`Esc` 走 capture 阶段并 `stopPropagation`，不会漏到全局 Esc | 非破坏性 |
| `WelcomeWizard`（开始使用 / 更换影像） | `×` / `Esc` / 点遮罩 / 「取消」 | **= 取消，不保存任何改动**（只有「开始使用」才会 `setDataPaths`） | 非破坏性 |
| `DetectSettings`（检测参数） | `✕` / 「关闭」 | **= 只关窗**。参数是即时生效并持久化的，关窗**不回滚**已改的参数（按钮因此不叫「取消」） | 非破坏性，但**不是撤销**（见 4.3） |
| `ExportDialog`（导出交付包） | 「关闭」 | 只关窗，不产出任何文件（也不会置 `exported`） | 非破坏性 |
| `DerivedDialog`（生成高度图 / 林地边界） | `×` / 点遮罩 / 「取消」/「知道了」 | 只关窗。**生成中（`running`）禁止关闭**：`×` 置灰、点遮罩无效 | 非破坏性（生成**一旦开始**会覆盖旧文件，但那是"开始生成"的后果，不是取消的） |
| `PreflightDialog`（检测前预检） | 「取消」 | 不开始检测，什么都不改 | 非破坏性 |

### 3.1 哪些弹窗**没有** Esc / 点遮罩退出

如实记录（不是设计意图，是现状）：

- `DetectSettings`：无 Esc、无遮罩（它是个挂在工具栏下沿的浮层，没有遮罩）。
- `ExportDialog`：无 Esc、无点遮罩退出，只有「关闭」按钮。
- `DerivedDialog`：无 Esc（有 `×` 与点遮罩）。
- `PreflightDialog`：无 Esc、无点遮罩，只有「取消」按钮。

统一它们属于**下一轮**的事：目前只保证"已经有的退出方式都是非破坏性的"。
（`ResumeDialog` 的 Esc 曾经只 `preventDefault` 不 `stopPropagation`，会把全局 Esc
漏出去清掉地图选中 —— 已修，见 4.1。）

## 四、逐个弹窗的确认说明（都对照过代码）

### 4.1 `ResumeDialog` —— `×` / `Esc` / 点遮罩 = 继续

- `×` 的 `onClick` 与 `Esc`、点遮罩走的都是同一个 `onContinue`。
- `Esc` 用 **capture 阶段 + `stopPropagation`**（与 `WelcomeWizard` 一致）。
  以前它只 `preventDefault`，于是 App 那个全局 Esc（退出绘制 / 清空地图选中）照样执行 ——
  "按 Esc 关弹窗"会顺手把用户选中的一批多边形清掉。同一个 `window` 上的两个监听器，
  只有 capture 先跑且 `stopPropagation`，才能让后面的冒泡监听器不再被调用。
- 为什么"关掉"选"继续"而不是"重新开始"：两个动作后果不对称（见第五节）。
- 正文里现在明确写着「点右上角 × 或按 Esc = 继续使用上次的结果（什么都不变）」——
  以前这句只写在 `×` 的 `title` 里，用户是**点了之后**才发现它是继续。
- 「换一张影像」**只打开向导，不清任何数据**。向导取消 → 本弹窗自动回来
  （App 的渲染条件是 `resumeAsk && !wizard`，弹窗状态从未被清掉）。
- 「重新开始」清的是**界面上的结果与圈选范围**（`setGaps([])` + `setRoi(null)`），
  不删磁盘文件。为什么连圈选一起清：不清的话 `hasRoi` 仍为 true → 第 2 步算"已完成"
  → 界面直接落到第 3 步，用户看到的是"我点了重新开始，怎么跳第 3 步了"。
  这跟向导 B2 分支（2026-10-24 的修复）是同一套语义，所以按钮上的「第 2 步」是**定值**。

### 4.2 `WelcomeWizard` —— `×` / `Esc` / 点遮罩 = 取消

- 三种取消方式都走 `onCancel`，而 `onCancel` 现在只做两件事：
  `setWizard(null)` + 往日志里写一句「已取消更换影像：界面与结果保持不变」。
- 「开始使用」= 提交，且**是唯一会改数据的地方**：
  `setDataPaths` → 重启瓦片服务 → 等 `/meta` → `onWizardDone`。
- `onWizardDone` 之后按三种意图分流（判据见 `lib/gapsLoad.ts`）：
  - **A**：用户在向导里**亲手选过**结果文件 → 载入他指定的那份；
  - **B1**：换到了另一张影像、而那张影像自己跑过 → 载入那张自己的结果；
  - **B2**：其余（新影像没跑过 / 又选了同一张想重新开始）→ 按「重新开始」处理：
    清界面结果、清圈选、跳过紧随其后的自动载入。
- `Esc` 用 capture 阶段并 `stopPropagation`：不然会同时触发 App 的全局 Esc
  （退出绘制 / 清选中）。"正在启动中"（`busy`）时不允许取消 ——
  后台正在重启瓦片服务，中途关掉会留下半启动状态。

### 4.3 `DetectSettings` —— 「关闭」只关窗，不回滚

- 每个控件 `onChange` 直接 `setDetectParam(...)`，并且参数是持久化的（localStorage）。
  所以关窗 = "我改完了，关掉"，**不是** "我刚才改的都不算"。
- 因此底部按钮叫 **「关闭」**（以前叫「取消」，那是骗人的），窗内也写明了
  「改动会立即生效并记住；想回到默认值点「恢复推荐值」」—— 回滚的入口指向
  「恢复推荐值」，一个**明确**的动作。
- 为什么不真做回滚：参数可能正被一次运行中的检测读着，回滚会造出
  "界面显示的参数 ≠ 这次检测实际用的参数"，比多点一次糟得多。
- 有没有「开始检测」按钮由 App 的 `settingsIntent` 决定：`'detect'` 才有
  （来自「开始检测」与步进器第 ③ 步），`'edit'` 没有（来自「更多 → 检测参数」）。
  关窗时 App 会把它复位成 `'edit'`，所以"这次带不带主按钮"不会漏到下一次。

### 4.4 `ExportDialog` / `DerivedDialog` / `PreflightDialog`

- `ExportDialog`：导出是"点按钮才开始"的动作，关窗不产出文件、也不置 `exported`。
  唯一副作用是选目录时会记住选择（`setOutputDir`，那是用户明确选过的）。
  导出**成功**之后（`out.ok !== false`，文件已落盘）才 `markWorkflow({ exported: true })`
  —— 第 ⑤ 步的完成位只能在这里置上：失败的导出不能算"已交付"。
- `DerivedDialog`：`running` 阶段三种关闭方式全被封住（`×` disabled、遮罩判断
  `phase !== 'running'`），因为中途打断会留下半个高度图，而检测读到它不会报错。
- `PreflightDialog`：「取消」= 不开始检测。它没有自己的状态，`setPreflight(null)` 即结束。

## 五、为什么「取消」必须是无操作

因为**两个方向的代价完全不对称**：

| | 取消做错了（= 误清数据） | 取消做对了（= 什么都不变） |
|---|---|---|
| 后果 | 界面结果被清空、步骤倒退、圈选/人工编辑计数/撤销历史一起归零（`setGaps` 会重置 `workflow`、`past/future`、`manual*`、内存里的验证集进度） | 用户再点一次就行 |
| 恢复成本 | 想拿回结果只能**重跑约 6 分钟**，人工复核的工作**不可恢复** | 0 |
| 发生概率 | 高 —— `×` / `Esc` / 点遮罩是"手滑"三大高发动作 | — |

而"重新开始"这个动作本身**有专门的按钮**（弹窗里的「重新开始」、向导里的
「开始使用」）。也就是说：想做破坏性操作的人有明确入口，
所以**没有任何理由**让"关闭"也具备破坏性。

2026-10-24 修的那个 bug 正是这条规则的例外：`onPickNewResume` 在打开向导的
**同时**就清了结果，于是"点 × 取消"变成了"结果没了 + 步骤从第 4 步掉回第 2 步"。
用户的原话是「这不符合逻辑」—— 他说得对：**取消不产生副作用**才是符合直觉的模型。

## 七、改代码时的纪律

- **不要**在"打开某个弹窗"的回调里清数据。清数据只允许发生在**明确的提交动作**里
  （向导的「开始使用」、弹窗的「重新开始」/「继续复核」、导出窗的「开始导出」）。
- 新增弹窗时，先决定它的 `×` / `Esc` / 点遮罩走哪一支，并写进第三节的表里。
- 任何"步骤会跳"的逻辑都要能在 `lib/workflow.ts` 里找到依据；找不到就是写错了地方。
- 改完请跑：`cd desktop && npx tsc --noEmit && npm test`。
