# 界面设计规范 · Ark UI（工业信息系统）

> 2026-10-24 起，桌面端视觉按《Ark UI 设计系统》重做。本文只记**这个项目怎么落地**，
> 不复制规范原文（规范在 `~/.workbuddy-ai/skills/ark-ui/`）。

## 1. 设计契约（改样式前先读）

```
family   ark        黑白青工业信息系统（近黑底 / 纸白字 / 青色信号）
depth    2 / moderate
证据      design-language.md「Stage plus instrumentation / Editorial hierarchy /
          Controlled accent / Layered flatness」+ recipes.md「Ark」+ depth-levels 的 2 级清单
主屏任务  一眼看清「当前在哪一块、走到第几步、下一步点什么」，其余面积留给地图
不做什么  不做启动序列、不做角色美术、不加第二信号色、不用圆角 / 卡片 / 投影
```

**为什么选 ark**：这个工具的本质是"看一张大影像 + 一堆读数"，ark 的
*stage plus instrumentation*（舞台 + 边缘仪器）正好是这件事的形状；青色作为唯一信号色，
在深色影像上辨识度最高，也不会和类别色（数据色）打架。

**为什么是 2 级**：产品型 UI 的默认档。外壳与共享控件（工具栏 / 步进器 / 面板 / 弹窗 /
菜单 / 状态栏）全覆盖 + 一层蓝图舞台（地图四角括号 + 底纹），不做多区舞台与逐屏编排。

## 2. 两层结构

| 层 | 文件 | 职责 |
|---|---|---|
| 布局层 | `desktop/src/styles.css` | 网格、定位、响应式、动画（别动布局） |
| 设计层 | `desktop/src/ark.css` | 外壳语法、索引、细线、信号色、动效 |

`main.tsx` 里 **`ark.css` 必须在 `styles.css` 之后 import** —— 顺序反了整层静默失效。
改配色/语法只改设计层；改布局只改布局层。

## 3. 令牌（`styles.css` 的 `:root`）

| 用途 | 变量 | 值 |
|---|---|---|
| 舞台底（近黑，不是纯黑） | `--ark-ink` | `#080a0b` |
| 面板 / 浮层 | `--ark-panel` | `#0c1114` |
| 输入底 | `--ark-field` | `#141b1f` |
| 主线 / 次线 | `--ark-line` / `--ark-line-strong` | `#2b353a` / `#3d494f` |
| 主文字（纸白，不是纯白） | `--ark-paper` | `#f4f6f6` |
| 次要文字 | `--ark-muted` | `#8d9396` |
| **唯一信号色** | `--ark-signal` | `#18d1ff` |
| 状态：已验证 / 在线 | `--ark-state` | `#c8eb21` |
| 状态：注意 / 错误 | `--ark-warn` / `--ark-error` | `#ffb020` / `#ff5a5f` |

旧的 `--bg/--panel/--text/--dim/--accent` 保留为**别名**（值换成 ark 的）——
3000 行样式里引用 300+ 次，改名只产生纯机械的大 diff。

**为什么近黑不纯黑**：纯黑会和深色影像焊死，看不出地图边界；`#080a0b` 留了一点分离度。

## 4. 语法（这一层决定"像不像 ark"）

| 元素 | 做法 |
|---|---|
| 外壳 | 56px 黑顶栏：品牌块（压缩体大写 + 微标签 + 左侧青色信号条）→ 步进器 → 工具图标 |
| 索引条 | 顶栏下方 26px 等宽小字：`BLOCK / STEP 02/05 / RECORDS / SERVICE`，**只放真实数据** |
| 步进器 | `01`–`05` 编号 + CJK 标签；当前步 = 青色文字 + **2px 青色下划线**（全系统唯一的"我在哪"信号） |
| 步间刻度 | 步与步之间是 **1px 竖刻度**（不是方块）：未走过 9px 暗线、已走过 14px 半亮线 —— 长度差就是"走到哪"的反馈 |
| 面板标题 | `01 / 图层与类别`、`02 / 复核` —— 索引用等宽青色，标题用 CJK 半粗 |
| 读数块 | **不做卡片**：一条 1px 顶线 + 21px 压缩体大数字 + 11px 微标签（Editorial hierarchy） |
| 分组 | 只用横线分隔，不用盒子（盒子会把 4 个分组读成 4 张卡片） |
| 按钮 | 方形 1px 描边；主操作 = 青色实心 + 深色字 + 左侧 3px 信号条；悬停只改色 |
| 弹窗 | 黑面 + 1px 边 + **顶部 2px 青色规则线**；入场是 clip-path 自上而下揭开（位移+裁切，不是缩放） |
| 检测参数窗 | 与其它弹窗**同一层**（`.ds-mask`，z-index 1050）：居中 + 窗内自滚 + 标题吸顶 / 主操作吸底 |
| 地图舞台 | 左上/右下**两个角括号**（1px 青色 55%）+ 全屏 45° 细斜纹底（1.4% 不透明） |
| 状态栏 | 底部等宽元信息基线；在线点用 `--ark-state` |
| 动效 | 直接交互 180–220ms；只有"检测中"的进度填充做 1.8s 呼吸（全系统唯一循环动画） |

## 4.1 两条容易踩的布局约束

1. **工具栏必须有确定高度**（`height: 56px`）。只写 `min-height` 时，步进器的
   `height: 100%` 会解析成 `auto`，当前步那条 2px 下划线就贴在第二行文字上
   （用户截图里"运行中"被线切了）。
2. **模态不要用 `position: absolute`**。绝对定位的后代同样计入文档可滚动区域 ——
   参数窗内容一长就把整页撑出滚动条，滚轮滚的是页面而不是窗内。用
   `position: fixed` 遮罩 + `max-height` + `overflow-y: auto` + `overscroll-behavior: contain`。
3. **`flex-basis` 优先于 `width`**。步间分隔线被写成 `flex: 0 0 18px`，设计层只改
   `width: 1px` 是无效的 —— 它会渲染成 18×14 的方块（用户看到的就是"左边那个正方形"）。
   改宽度必须同时覆盖 `flex`（或 `flex-basis`）。

## 5. 有意偏差（都不是遗漏）

1. **语义状态色有三个**（青=信号、酸绿=已验证、琥珀/红=注意/错误）。规范说"一个信号色"，
   但这是数据工具：过期结果与错误必须能和"正常选中"区分。三个里只有青色进入装饰层，
   另外两个只出现在小面积文字/左沿。
2. **窄窗（≤1180px）恢复步骤标签**。`styles.css` 原本在这个断点把除当前步以外的标签全藏了，
   导航退化成 `01 02 03 04 05` 五个光秃秃的编号 —— 规范明令禁止"把决策 UI 压成无标签编号"。
   设计层恢复了标签，让步进器横向滚动；真正省掉的只有 `.sr-sub`（副信息在索引条里也有）。
3. **类别色仍是数据色**（`lib/classes.ts` 的 9 个）。它们同时用于地图填充与图例，
   属"产品数据"而非装饰；已按深底提亮一档（见 `CLASS_STYLES`）。

# 第二轮：depth 2 → 3（2026-10-25，分支 `feat/ui-ark-v2`）

> 本文上半部分记的是 depth 2 的契约，**大部分仍然有效**（令牌、两条硬规矩、
> 两层结构、`ark.css` 必须后 import）。这一节只记"升级到 depth 3 改了什么、
> 为什么改、以及哪些建议被**否决**了"。
> 逐组件的语法细节见 `组件语法规范-depth3.md`（设计系统专家产出，实现有偏差，见 §5）。

## 1. 新的设计契约

```
family   ark        不变
depth    3 / complex（原 2 / moderate）
主屏任务  不变：「当前在哪一块、走到第几步、下一步点什么」，其余面积留给影像
新增要求  外壳多区化（顶栏 / 索引 / 舞台 / 命令条 / 状态基线）
          + 全共享组件统一（弹窗 / 菜单 / 筛选 / 列表 / 空态 / 折叠轨）
          + 窄窗真重排（1180 / 980 / 820 三档）
不做什么  不加第二信号色、不用圆角、不用投影（遮罩除外）、不做假仪表
```

## 2. 布局重构：从"浮层压影像"到"舞台 + 底部栈"

这是本轮唯一的结构性改动，其它都是语法收口。

```
改前  .body = [左 288] [地图(浮着卡片+批量栏)] [右 300]
改后  .body = [左 288 | 28] [地图列] [右 300 | 28]
                             └ 地图列 = .map-wrap（flex:1） + .batch-bar（40） + .next-card（64 | 28）
```

| 变化 | 原因 |
|---|---|
| 「下一步」卡片 → 地图列下沿**命令条** | 原卡片 330px 浮在右下角，遮住的正是用户判断"这块是不是空地"时唯一要看的东西 |
| 批量操作栏 → 命令条上方的**通栏行** | 两者原本抢同一块空间，靠 `.next-card.raised{bottom:72px}` 硬躲，选中项一多就顶进影像中部 |
| 左右面板可折叠成 **28px 竖轨** | 900×760 实测：288+300 把地图挤到 312px，用户看到的是一片"加载失败的黑" |
| 断点自动折叠（1180 / 980） | 纯手动 → 用户不知道能折；纯自动 → 大屏上手折了会被强行展开。现在是"断点定默认值，手动选择作为 override，只有断点变化才作废" |
| 状态栏 120 → **56px**（折叠日志） | 4~5 行 10px 灰字常年在动，把"影像已就绪 / ROI / 分辨率"挤到左边一窄条。展开仍回到 `--status-h`（可拖） |

**⚠️ 必须一起改的一条**：`MapCanvas` 补了 `ResizeObserver → map.resize()`。
MapLibre 只监听 **window** resize，而这一版容器高度会**在不改窗口大小的情况下**变化
（命令条展开/折叠、批量栏出现、侧栏折叠）。不补这条，canvas 被 CSS 拉伸、
影像纵向压扁，而多边形是矢量图层 —— **图形与影像错位**，量面积的人会直接算错。

## 3. 新增的 4 个令牌（只有这 4 个）

| 令牌 | 值 | 替换掉的散落字面量 |
|---|---|---|
| `--ark-bar` | `3px` | 左面板 8×8 色块 + 复核行 8×8 色块 |
| `--ark-hair` | `rgba(244,246,246,.12)` | 四处 `.07/.12/.18/.22` 细线 |
| `--ark-scan` | `rgba(24,209,255,.10)` | 四档选中底色 `.10/.12/.14/.16` |
| `--ark-dock-h` | `64px` | 命令条展开高度（折叠态 28px 用字面量） |

## 4. 语法收口（每一处都在修一个"自相矛盾"）

| 元素 | 改前 | 改后 | 为什么 |
|---|---|---|---|
| 步进器编号 | 19px 圆底徽章，完成态是**青色实心圆** | 纯等宽文字，靠字色 + 2px 下划线 | `StepRail.tsx` 的注释早就写"索引而不是对勾"，CSS 却画了 3 个青色圆 —— 直接吃掉全屏青色预算 |
| 当前步 | 底块 + 描边 + 下划线（3 个信号） | 只留下划线（1 个信号） | 底块会让顶栏读成一排标签页 |
| 面板头 | flex + space-between，标题变长先挤扁计数 | 5 列 grid，只有标题列可伸缩 | 计数是决策数据，标题是固定词 |
| 类别行 | 复选框 + 独立 8×8 色块 | 行左沿 3px 竖条 + 复选框 | 两个同形方块在 12px 下被读成"两个勾选框"（用户实测反馈） |
| 分组头 | 与类别行同样式 | **通栏填充**（容器语法），与竖条不重叠 | 填充 = 这是一组，竖条 = 这是某一类 |
| 复核筛选 | 4 个 999px 圆角胶囊 | 4 片双行仪表片（计数落同一基线） | 胶囊是 POPUCOM 语法；横排会把「人工新增」推出视口 |
| 面积档 | `最小面积` 四字 + 5 档 + 输入 + 单位挤成竖排单字 | 4 档等宽 grid + 58px 输入，单位走伪元素 | 300px 宽下 flex 每段都要最小宽度，必然换行错位 |
| 复核行 | flex，面积 `min-width:62px` | grid，面积列**定宽 88px** | 每行是独立 grid，`auto` 会按每行自己最宽的数字定宽 → 类别名逐行错位 |
| 复核/验证集 | 外层 tab「复核」+ 内层「复核｜验证集」 | 三档平级：**清单｜验证集｜属性** | 同一个词在同一列出现两次，用户分不清层级 |
| 弹窗 | 3 套外壳（460/540/700/720 四档宽） | 一套外壳（零圆角 + 2px 顶线 + 无投影），宽度保留 | 真正的差异是**滚动归属**，不是外观 |
| 圆角 | 8/11/12/14/999 五档并存 | 全部 0（只有 `.dot` 是圆点，那是指示灯） | 五档圆角读起来像三套组件库 |
| 空舞台 | 纯黑（"软件坏了"） | 蓝图网格 + 一句"缺什么、怎么补" | 离线时地图区是唯一没有信息角色的面积 |

## 5. 被**否决**的两条专家建议（有意偏差，不是遗漏）

| 建议 | 否决理由 |
|---|---|
| **L2 测量刻度带**（四边 0–14px 内侧刻度，配 `100 px · ≈ 3.3 m` 标签） | 与 MapLibre 的 `ScaleControl`（左下角真实比例尺，显示"200 m"）**功能重复**。一条没有标签的刻度带不回答任何用户问题，只增加密度 —— 违反 skill 的"每个装饰必须支持分组/方向/状态/世界构建"。测绘用户读的是比例尺上的"200 m"，不是屏上像素格 |
| **L3 底边进度规则线** | 与顶部 `DetectBar` 的 2px 进度条**同值重复**。skill 明令"不要为了填满空间而镜像同一个遥测值" |

替代方案：depth 3 的第二层舞台用**空舞台**（蓝图网格 + 中央 dossier）。
它是有信息角色的层（"这里本该有影像"），且只在离线时出现，不占用有影像时的任何面积。

## 6. 统一弹窗的 Esc 语义（本轮补齐）

`lib/dialogKeys.ts` 的 `useEscapeClose`：**capture 阶段 + `stopPropagation`**。

为什么必须 capture：`App` 在 window 上挂了全局 Esc（退出绘制 / 清空选中），
弹窗的 Esc 也是 window 级 —— 同一 target 上只有 capture 先跑并阻止传播，
才能不让"关弹窗"顺手清掉用户刚框选的一批多边形（`ResumeDialog` 踩过）。

本轮新接入：`ExportDialog`（busy 时不响应）、`DerivedDialog`（running 时不响应）、
`PreflightDialog`（busy 时不响应）。至此 7 个弹窗全部支持 Esc。
