跨机器协同：Google Drive 放置清单

公司机 ↔ 家用机 · 什么走 git、什么走网盘、放之前注意什么  ·  2026-10-15
这份是跨机器协同的操作清单：为了让公司机与家用机看到同一份结果， 你需要往 Google Drive 放哪些东西、怎么放、以及哪些千万别放。

一句话结论：放 output/（检测结果，324 MB）+ segment.tif 和 tree_info.json（共 3 MB）； 891 MB 的 dsm.tif 和 3.5 GB 的正射影像都不用放。

一、必须放的：output/ 整个目录

整个 output/ 目录324 MB
├─ arcgis/（ArcGIS 交付包，最重要）24 MB
├─ jobs/（瓦片缓存 + 运行日志）133 MB
├─ chm.tif（冠层高度模型）60 MB
└─ wgr17-elev-gaps.geojson（最新检测结果）25 MB

为什么必须放：

  • output/ 是运行产物，每次重跑内容全变，进 git 会让仓库迅速膨胀
  • output/arcgis/ 是要交给业务方的交付包，两台机器都得能取到
  • output/chm.tif 是海拔证据的输入，缺了它精度会掉（见第四节）
⚠️ 放之前先看一眼时间戳。 output/ 随时可能被重跑覆盖。跨机器取用时， 先确认文件时间是不是你要的那一版，避免拿到旧结果。

二、建议放的：DSM 相关文件（区分"必须"与"可选"）

这几个文件在 D:/学习目标_笔记/2. 智/计算机/自学/9. 人工智能/项目类型/图像识别/Forest-Gap-Detection/drone data/，是航测工程的原产物。 它们的必要性差别很大，别一股脑全放：

文件体积作用必要性
segment.tif2 MB 航测软件 AI 的语义分割（树/水/建筑） 必须放
管线运行时直接读它， 缺了精度会明显下降
tree_info.json1 MB 16,544 个树心坐标（含高程） 建议放
用于网格互证与参考点重建
dsm.tif891 MB 立体高度图 —— 生成 CHM 的原料 可选
见下方说明
关键：dsm.tif 其实可以不放在网盘。
因为 output/chm.tif（60 MB）已经在同步范围内—— 它正是由 dsm.tif 加工出来的成品。所以另一台机器直接就有 CHM 可用。

只有当你要重新生成 CHM（改了参数、或换了新的园区影像）时，才需要 dsm.tif。 那种情况把 891 MB 单独拷一次就行，不必长期占用网盘配额。
放与不放的取舍：
· 放 segment.tif + tree_info.json = 约 3 MB， 换来另一台机器完整精度 —— 非常划算；
· dsm.tif 891 MB 长期占配额，而它的产物 CHM 已在同步， 按需临时拷贝更合理。

三、千万不要放的

内容体积为什么不放替代方案
WGR17-002.tif（正射影像）3.5 GB 太大，且是原始数据，不会变 每台机器本地各存一份
models/（模型权重）约 430 MB 体积大，且有公开下载地址 跑 一键配置环境.bat 自动获取
.venv/（Python 环境）约 1 GB 与环境相关，换机器必须重建 跑 一键配置环境.bat
.git/— 会与本地 git 冲突，可能损坏仓库 用 git push/pull
🚫
特别提醒：不要把整个项目文件夹放进 Google Drive 同步。
其中的 .git/ 与 .venv/ 被网盘同步会出各种奇怪问题 （文件锁冲突、软链接失效、仓库损坏）。只同步 output/ 和 DSM 三件套。

四、建议的 Google Drive 目录结构

Google Drive/
└── ForestGapDetection/
    ├── output/                  ← 直接同步整个目录（324 MB）
    │   ├── arcgis/              ← ArcGIS 交付包（要交出去的）
    │   ├── jobs/                ← 瓦片缓存与日志
    │   ├── chm.tif              ← 冠层高度模型
    │   └── wgr17-elev-gaps.geojson
    └── 航测原产物/               ← 只放小文件（3 MB）
        ├── segment.tif          ← 必须
        └── tree_info.json       ← 建议

两台机器怎么用：

  1. 每台机器把 ForestGapDetection/output 设为本地 output/ 的同步目标（Google Drive 桌面版可指定任意本地文件夹同步）
  2. DSM 三件套解压/复制到各机器本地 D:/学习目标_笔记/2. 智/计算机/自学/9. 人工智能/项目类型/图像识别/Forest-Gap-Detection/drone data/
  3. 跑管线时把 --segment 指到本地的 segment.tif

五、每次干活的标准流程

【开始前】
  1. git pull                      ← 拉取另一台机器的代码/文档改动
  2. 确认 output/ 已同步完（看时间戳）

【干活中】
  3. 改代码 / 跑算法

【结束后】
  4. 跑契约测试：期望 95/95
     python scripts/test_sidecar_contract.py
  5. git add / git commit / git push   ← 代码与文档走 git
  6. 等 Google Drive 同步完 output/     ← 结果走网盘
  7. 在下班前确认同步图标变绿
