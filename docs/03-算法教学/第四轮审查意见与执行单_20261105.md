### R1 · P1 · Python 株位吸附不是"最近格点"，交付点与地图点对不上

- **现象**：`scripts/planting_points.py:263-267` 用 `xy_to_grid` 后分别 `round(gx)`、`round(gy)` 再 `node_at`。
  三角格网上这不是最近格点：`xy_to_grid` 的 `gx` 用连续的 `gy` 扣错行偏移，`node_at` 用取整后的行，且只看一行。
  起点离最近格点 > 3.70 m 时有 16.6% 的概率选错（差半个到一个株距）。
  前端 `desktop/src/lib/estimate.ts:184 nearestNode` 是对的（试 floor / ceil 两行取近者）。
- **怎么触发**：用户在复核里把"不确定 / 林间空隙"改成"株位空缺"（这类空地的质心本来就离格点 3.7~4.9 m，
  且第四轮给所有可种类别都写了 `lattice_origin_*`）；凹形株位空缺（起点是面内点）。交付导出走 Python，地图走 TS。
- **真实数据上有多常见**（第二遍审查，用本园第四轮结果模拟人工改判）：算法自己判的株位空缺 0/355 受影响；
  人工把"不确定"改成株位空缺 16/310 块偏移（中位 4.4 m），"林间空隙"改过来 8/118（4.4 m），"连片空地"改过来 28/211（6.3 m）。
  初审说的"约一半"只对离格点 3.7~4.9 m 的起点成立，按块数约 5%~13%，但每一块都偏一整个株位。
- **决策**：Python 改成与 TS **同一个算法**（投影到 (du, dv)，对 `j ∈ {floor(dv/row), ceil(dv/row)}` 取
  `i = round((du − j·skew)/pitch)`，取距离最小者）。**不要**反过来改 TS。
  最好把这个函数放进 `grid_prior.GridModel`（如 `nearest_node(x, y)`），`planting_points` 与将来的调用方共用。
- **验收**：
  1. 新增 Python 测试：起点离格点约 4 m 的株位空缺 → 点 = 面内最近格点；
  2. **Python / TS 共用夹具**：同一组 GeoJSON（至少含：凸形株位、凹形株位、改判来的株位、带洞多边形）
     分别跑 `generate_planting_points` 与 `estimate()`，逐点距离 < 1 cm、点数相等；
  3. 全幅 `eval_grid.py` 指标不变或更好（第 5 节基线）。

### R2 · P1 · CHM 格网只看对比度就采用，模型不对时全园"不确定"或株距错几米，且不退回旧勘察

- **现象**：`scripts/process_image.py:2063 grid_from_chm` 只在顶点 < 200 或对比度 < 50 时退回 RGB 勘察。
  `lattice_from_tops` 永远按**等边三角**拟合（`skew = pitch/2`、`row = pitch·sin60°`），某一个倒格方向对上就能有上千的对比度：
  - **正方形 / 矩形种植**（合成 7.5 / 8.0 m 正方形、8.45×7.3 m 矩形）：对比度 1,238~4,445 → 被采用；质量 `q` 0.058~0.080 < 0.15
    → `GridModel.is_usable == False` → 全园空地"不确定"、置信度 0。旧勘察支持正方形，却**不会被调用**；
  - **等腰三角种植**（合成 9.0 × 7.5 m）：被拟合成 8.659 m 等边，对比度 5,424、`q` 0.818 → 照样采用；局部相位只钉住空地质心，
    离质心 20 / 50 / 100 m 处真实格点偏 0.51 / 1.36 / **2.56 m** → 大块连片空地的放样点偏到行间。
  - 另：`relabel_with_local_lattice` 里 `g_loc = dataclasses.replace(grid, origin…)` **继承全局 quality**，局部相干度 0.9 的空地也救不回来。
- **本园不受影响**（`q = 0.527`），但换园区会整园失效或整园偏移，而且**不报错**。
- **决策**（三条都做）：
  1. **模型检验用"非相干、逐方向"拟合，不要用全局相干能量。** ⚠️ 审查方初稿写的"三方向相干峰能量 min/max 比值"**作废**：
     本园真实 CHM 上三个方向的相干能量是 [29, 1584, 0.45]（min/max = 2.8e-4，各种植块相位互相干涉），与坏例子
     （正方形 2.4e-6、矩形 4.6e-5、等腰 7.5e-5）只差一两个数量级，阈值取哪里都脆。正确做法：把顶点按约 100 m 窗口分组，
     对每个方向**分别**求 Σ_w |S_w(k)|²（窗口内相干、窗口间非相干）并拟合该方向的间距与角度。本园实测（120 个窗口）：
     三方向能量 3,224 / 3,975 / 3,380（均衡），间距 7.439 / 7.411 / 7.448 m，两两相差 60°。
     **判据**：三个间距相互差 ≤ 1%、方向两两夹角与 60° 差 ≤ 1° → 是等边三角种植；否则 `grid_from_chm` 返回 `None`、
     日志写明原因，退回旧勘察。阈值（1% / 1°）由执行方用本园与合成正方形 / 矩形 / 等腰各至少 3 个随机种子复核后写进常量。
  2. **局部质量**：`g_loc` 的 `quality` / `regularity` 用**该空地的局部相干度**，不继承全局中位数。全局 `q < 0.15` 时只打警告、不退回
     （模型检验已经挡住了模型错的情况；混合场景靠局部质量逐块处理）。
  3. **局部相位门槛随支撑点数缩放**（原第二轮格网发现 #5）：现门槛"相干度 ≥ 0.2 且 ≥ 12 个顶点"对纯随机点的通过率
     N=12 时 40%、N=20 时 20%，林缘 / 稀疏块会拿到随机相位；而第 2 条让局部相干度直接当质量，问题会被放大。
     改为 `coherence ≥ max(0.2, sqrt(ln(1/α)/(2N)))`，α = 1%（N=12 → 0.44、N=31 → 0.27、N=65 → 0.19）。
     本园局部支撑最小 31、0/994 块受影响 —— 改完本园结果应不变，这本身就是验收项。
- **验收**：合成正方形 / 矩形 / 等腰 → 退回旧勘察（日志可见原因）；合成"三角种植 35% + 随机林 65%" → 种植区内空地不全是"不确定"、
  林区空地是"不确定"；纯随机点（N = 12~20）通过局部门槛的比例 ≤ 1%；本园全幅指标与第 5 节基线一致
  （`q`、确定需补种、`eval_class.py` 各行差异 < 0.5%）。

### R3 · P2（第四轮引入的回归）· 每块空地各用各的相位后，重叠多边形的放样点去重失效

- **现象**：去重按"坐标取整到 cm"（Python `planting_points.py:231/282`）/ "经纬度 7 位小数"（TS `estimate.ts:311`）。
  以前全园一个原点，重叠处格点坐标完全相同，自然去重；现在检测空地用局部原点、手画空地（`addGap` 不写 `lattice_*`）

  有局部相位的检测空地 > 全局相位的检测空地 > 手画 / 编辑过的空地；同级按要素原顺序。
  Python 与 TS 用同一规则（R1 的共用夹具里加一个重叠用例）。**不要**给手画空地"借"邻近空地的相位来规避 —— 那只修了一种重叠。

### R10 · P2 · 有证据才做 · 周期图相干求和受分块相位干涉影响

- **现象**：能量是全园所有顶点的**相干**求和，不同相位的种植块互相干涉，峰位随机偏移（合成：株距 ±1~2%、方位 ±2°）。

### R13 · P1（质量上限）· 大块连片空地退回全局相位，一半以上的放样点没对上树行

- **现象**：`relabel_with_local_lattice`（`process_image.py` ~2147）对每块空地只取**一个**圆（质心为圆心、半径 = 最远顶点距离 + 40 m）
  里的树冠顶点求相位。大块 / 狭长空地的这个半径达 200~520 m，圆里包含好几个相位不同的种植块 → 相干度 < 0.2 →
  `lattice_phase = "global"`。全局相位正是本轮要淘汰的"与真实树位不相关"的那个相位。
  日志还把原因写成"周围树太少"——这些空地的支撑顶点有 91~10,024 个，原因是**相位混叠**，不是树少。
- **审查方实测**（`desktop/tmp/ab/eval_phase.py`，大疆树心作裁判，两种瓦片切法结果一致）：

  | 连片空地 | 块数 | 面积 | 放样点 | 到真实树行 P50 | 1 m 内 |

  | 局部相位 | 211 | 111,657 m² | 1,226 | **0.50 m** | **81.0%** |
  | 退回全局相位 | 25 | **134,404 m²（55%）** | **1,838（全部放样点的 54%）** | **2.54 m** | **10.1%** |

- **决策**：相位应当是**位置的函数**，不是"整块空地一个值"。
  1. 对单圆求相位失败（相干度不过门槛）的空地，改用**世界坐标锚定的 80 m 网格单元**（单元边界取 UTM 坐标的 80 m 整数倍，
     与瓦片怎么切、多边形什么形状都无关）：每个与空地相交的单元，用"单元中心周围 `40·√2 + 40` m 内的顶点"单独求相位，
     门槛用 R2 第 3 条的随支撑点数缩放的那个；
  2. 没有可信相位的单元（大空地腹地，周围没有树）**沿用最近的可信单元的原点**（先在同一块空地内找，再向外找），
     因为株距 / 方位全园一致，相位可以外推（参数误差 0.2% × 100 m = 0.2 m，可接受）；全都找不到才退回全局相位；
  3. 要素属性新增 `lattice_cells: [{cell: [i, j], origin_utm, origin_lonlat, coherence, support, source: "own" | "nearest"}]`，
     `lattice_phase` 取值增加 `"cells"`；`planting_points.py` 与 `estimate.ts` 按"放样点落在哪个单元就用哪个原点"排坑，
     单元交界处用 R3 的邻近去重（0.5 × 株距）；
  4. 已经是 `local` 的 994 块空地**行为不变**（它们已被验证，不要顺手改成单元法）；
  5. 日志改成如实区分："周围树太少" / "跨多个种植块、改用分单元相位" / "退回全局相位"三种各多少块。
- **验收**（缺一不可）：

     （预计会升 —— 点对上树行之后更容易碰到没被识别成树冠的小树，这是缺陷清单第 6 项的症状，不算本项失败）；
  3. 两种瓦片切法下 `eval_phase.py` 各行一致；Python / TS 共用夹具增加一个跨两个单元的大多边形用例，逐点一致；

### R14 · P1（第四轮引入）· 命令行会拿不重叠的 CHM 定全园网格（默认 `output/chm.tif` 是 WGR17 的）

- **现象**：`grid_from_chm`（`process_image.py:2063`）只检查 CHM 文件存在，然后读**整张** CHM 求周期图，从不核对它与输入影像是否重叠。
  CLI 的 `--chm` 默认值是 `output/chm.tif`。对另一个地块跑 `process_image.py --input other.tif`（不带 `--chm`）：
  逐瓦片融合读不到 CHM（窗口不相交 → `None`，旧行为、无害），但全园网格却用 WGR17 的株距 / 方位 / 原点，质量还很高（探针 0.992），
  所有空地按别人家的格网分类、放样，**没有任何警告**。桌面端不受影响（`lib.rs` 刻意不回退到共享的 `output/chm.tif`）→ 两条路径结果不同。
- **决策**：
  1. `grid_from_chm` 接收影像范围，只保留**落在影像有效范围内**的树冠顶点（有 ROI 时仍用整幅影像范围，参数估计样本越多越稳）；
     剩余顶点 < 200 → 返回 `None`、日志写明"CHM 与影像不重叠"，退回旧勘察；

     不满足只警告、不中断。这同时覆盖"不做"里的两个约定外输入场景（坐标系不同、分割图覆盖不全）；
  3. `--chm` 的默认值**暂不改**（改默认值会影响既有脚本与文档，第 1 条已经堵住了危害）。
- **验收**：合成用例：CHM 离影像 5 km → 退回旧勘察且有日志；本园结果不变；契约测试加一项 warn 事件。

### R15 · P2 · 瓦片指纹只记 CHM / 分割图的路径，不记内容

### R16 · P2（低）· 旧勘察的树冠判据没有按分辨率换算

- **现象**：`survey_grid` 调 `canopy_structural`（`process_image.py:532`）时既不传 `px_m`、也不传按参考分辨率换算的 `min_blob_px`，
  而瓦片阶段（`:945`）两样都传。结果：非 3.3 cm 的影像上，勘察与检测用的是两套树冠定义（10 cm 影像：勘察填 ≤ 36.7 m² 的孔、
  丢 < 20 m² 的树冠；检测填 ≤ 4 m²、丢 < 2.2 m²）。与第四轮"像素口径按参考分辨率"的原则不一致。本园（3.30 cm）数值不变。
- **决策**：`survey_grid` 传 `px_m=px_m` 与 `min_blob_px=px_area_at(min_canopy_blob, px_m)`；CLI 与 sidecar 都把 `min_canopy_blob` 传进来。
- **验收**：本园 `--no-elevation --grid-only` 的勘察结果与修改前逐位一致。

### R17 · P2（低）· 修复自交后拆出的"瓣"各自过面积门槛、各自成要素

- **现象**：`_own_core` 把反投影后自交的多边形修复成几瓣（只在一个点上相接），每瓣都当跨缝碎块；`stitch_seams` 里 `unary_union`
  不会把点接触的瓣并成一块 → 每瓣**单独**过 `min_area`、单独分类。后果：(a) 小瓣（< 30 m²）被丢；(b) 两瓣都够大时一块空地变两块要素；
  (c) 极端情况两瓣各 < 30 m² 而合计 ≥ 30 m² → 整块消失（第三轮之前会保留为一块）。
- **审查方在真实瓦片缓存上量过**：2048 配置 18 对点接触碎块，丢掉的小瓣合计 23.4 m²，(b) 0 例、(c) 0 例；
  1536 配置 20 对，小瓣合计 21.0 m²，(b) 3 例（84.7 + 39.9、122.4 + 67.0、193.3 + 108.1 m²），(c) 0 例。幅度很小，但 (b) 随瓦片切法而变。
- **决策**：同一个源多边形修复出的各瓣带同一个组标记（如 `_seam_group`）；`stitch_seams` 把"同组"或"点接触"的部分当作**一个**空地：
  面积门槛按合计面积判、分类按合并几何判；输出时这一组仍是一个要素 —— 用极小的正缓冲（≤ 1 mm）把点接触处连成有效的单个 Polygon，
  **不要**输出 MultiPolygon（下游约定每个要素是单个 Polygon）。缓冲带来的面积变化必须 < 0.01 m²/块，并保证"空地 ∩ 不可种植 = 0"不被破坏
  （缓冲后对同瓦片的不可种植多边形做一次差集）。
- **验收**：`test_stitch.py` 增加：两瓣各 20 m²、点接触 → 保留为 1 个 40 m² 要素；一大一小 → 1 个要素、面积 = 两瓣之和（±0.01 m²）；
  全幅 `metrics.py` 的重叠 / 跨类重叠仍为 0。

### 不做 · 证据图与正射影像坐标系不同时静默丢弃

两名反驳者都推翻了：三者同为 EPSG:4326 是 `ElevationEvidence` 写明的输入约定，`build_chm` 产出的 CHM 必带正射影像的 CRS，
桌面端也只会找同一导出目录里的伴生文件；且行为与第三轮之前完全相同，不是回归。
约定外输入的**警告**已并入 R14 第 2 条。

### 不做 · 分割图的无数据值（255）当成"非树"

反驳者 1 : 1。成立的部分：与"CHM 缺失 = 没有证据"的新规则不一致；分割图只覆盖影像一部分时，同一块地在"窗口部分落在分割图外"
（判非树）与"窗口完全落在分割图外"（退回 RGB）两种瓦片切法下结果不同。不改的理由：① 本园分割图完整覆盖影像，影像有效区内的 255

覆盖不全的情况由 R14 第 2 条的启动检查给出警告。遇到分割图覆盖不全的真实数据时再重新决策。

### 不做 · 阈值场构建时主进程内存峰值约 0.9 GB

两名反驳者都推翻：大数组是构造函数里的局部变量，建完即释放，只留下 89 × 94 的阈值场；不改变任何结果。
**可选优化**（不阻塞）：只有存在待处理瓦片时才建（全缓存命中 / 只合并时省 8 秒）。
