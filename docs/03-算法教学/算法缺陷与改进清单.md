## 1. 「需补种」口径：headline 数字里 14% 与它的语义自相矛盾

**事实**（`scripts/grid_prior.py`）：

```python
CLASS_SEMANTICS = {
    CLASS_ALLEY_GAP: "树冠之间的正常缝隙，无需补种",     # ← 说不用补
    CLASS_UNCERTAIN: "证据不足，需人工核实",            # ← 说没把握
    ...
}
UNPLANTABLE_CLASSES = (CLASS_ROAD, CLASS_WATER, CLASS_OFFICE, CLASS_UNDEVELOPED)
#     ↑ alley_gap / uncertain 不在其中 → 被计入「需补种」
```

`process_image.py` 的 `plantable_area = total_area`（= 剩下所有空地多边形之和），
因此 **1,655 要素版的 376,185 m² 里包含**：

| 类别 | 面积 m² | 占比 | 算法自述语义 |
|---|---|---|---|
| 连片空地 | 306,602 | 81.5% | 需按网格整片补种 ✅ |
| **不确定** | 40,089 | **10.7%** | 「证据不足，需人工核实」⚠️ |
| 株位空缺 | 17,050 | 4.5% | 补 1 株 ✅ |
| **林间空隙** | 12,445 | **3.3%** | 「正常缝隙，**无需补种**」❌ |

→ **52,534 m²（14.0%）的口径与语义冲突**。对外报一个数，容易让用户以为
"这 37.6 万 m² 都该补种"。

**建议**：报表拆成三档（不改算法即可实现）：
`确定需补种（连片空地 + 株位空缺）` / `待复核（不确定）` / `不计入（林间空隙）`。
或把 `alley_gap` 并入 `UNPLANTABLE_CLASSES`——但需先与用户确认语义。

## 2. 水体漏检 92%（已目视确认，机制清楚）

**实测**（探针 `probe_water.py` / `probe_water_to_gap.py` / `probe_water_crop.py`）：

| 量 | 数值 |
|---|---|
| DJI 语义分割标注的水体 | **7,625 m²**（58~65 个斑块，98.7% 在 ≥30 m² 斑块内，**无一个长宽比 ≥3 → 不是沟渠，是水塘**） |
| 其中满足我们蓝度规则 `B≥G>R` 的 | **7.9%（603 m²）** |
| 本项目实际检出水体 | 605 m²（8 块） |
| 水体像素中 CHM 缺失（NaN）比例 | **100%** |
| 水体像素被判「非树冠 → 空地候选」比例 | **100%（7,625 m²）** |
| **落在「需补种」多边形内的水体** | **5,691 m²**（另有 1,933 m² 落在 road/water/office 层内，被现有判据拦下） |

**机制链**（代码级）：
1. `build_chm.py` 主动把水面 mask 成 NaN（水面立体匹配失效，否则产生 ±20 m 假高程）；
2. `elevation.fuse_canopy()` 最后一行 `canopy = canopy & np.isfinite(chm)`
   ——「无有效高度处不可判为树冠」；
3. 于是水面上 `canopy=False` → 进入空地候选；
4. 唯一能拦下它的是 `landcover.detect_water()`，而它只认
   **蓝色（B≥G>R）** 或 **暗水（L<90 & ExG<15 & 纹理<6）**；
5. 实测 DJI 水体的 RGB 特征：**L 中位 121.7（P90=188.7）、S 中位 0.20、ExG 中位 12**
   —— 偏亮、低饱和、微绿 → **恰好落在所有判据的空隙里**。

**目视核对**（裁图已确认，`.workbuddy-ai/tmp/analyze/crops/`）：
- #1 3,163 m²、#2 2,138 m²、#3 1,378 m² 三个大斑块**都是真水塘**：
  岸线平滑、周边密林，#2 旁边还有道路 + 料堆 + **泵房**，#3 是裸土岸边的绿色浑浊水塘（藻类）。
- 绿色浑浊水塘（ExG 高）**天然不可能满足 `B≥G>R`**，这是判据的原理性盲区。

**建议**（按性价比排序）：
1. **把 `seg==water` 作为水体证据**（与 CHM/seg 判树冠同一思路）—— 一行代码，
   立刻覆盖 7,625 m² 里的绝大部分；
2. 蓝度规则加**形态学守卫**替代 `water_lum_max=160` 的一刀切：
   实测 `L≥160` 被砍掉 1,757 m² 蓝度命中，其中可能含浅色水塘；
   改为「蓝度命中 + 连通域 ≥30 m² + 低纹理」即可排除白路（白路是线状、纹理 0.7~8.0）；
3. 暗水规则 `L<90 & ExG<15` 全图命中 48,388 m²（几乎全是林下阴影），
   靠纹理门槛硬滤 —— 建议改为「暗 + 极低纹理 + **远离树心**」，提高可解释性。

## 3. 一半的「非树」判断完全依赖域外语义分割模型

**实测**（探针 `probe_chm_artifact.py` B 节）：

```
非树总面积 421,363 m²（占有效区 32.8%）
  CHM<1.2（高度明确低矮，硬证据）          206,536 m²  (49.0%)
  seg=other 且 1.2≤CHM<5.2（纯靠语义分割） 214,827 m²  (51.0%)
```

即 **214,827 m²（有效区 16.7%）的树/非树判定，CHM 完全不参与，全由 seg 说了算**。

风险来源（项目自己记录在案）：
- DJI 果树模型**支持列表里没有油棕**（只有 orange/litchi/banana/plum/persimmon/wogan），
  属域外推断，实测**漏检约 20%** 的树；
- 同一模型在 (27,12) 区块把裸地判成 76% 树（2026-10-16 实测）；
- 而 CHM 因为 DSM 被平滑，**系统性低估约 40%**（油棕真实 7~15 m → CHM 只读到 4~10 m），
  于是健康油棕的 CHM 常常落在 1.2~5.2 m 之间，**拿不到 CHM 救援**（必须 ≥5.2 m）。

**两条证据互相矛盾的面积**（同一批数据）：
- CHM 救援（seg=other 但 CHM≥5.2）：95,301 m²（占 other 的 19.3%）
- seg 独立判树（seg=tree 但 CHM<5.2）：99,974 m²
→ **两证据在约 19.5 万 m²（有效区 15%）上给出相反判断**，最终全靠融合规则仲裁。

**用 `tree_info.json` 做独立交叉验证**（探针 `probe_gaps_truth2.py` / `probe_baseline.py`）：
DJI 的**另一套**产物（果树树心表，与语义分割是两个不同模型）给出 15,190 个树心
（去重后），投到本结果上：

- 落在空地块内的树心 **563 个（占全部树心 3.7%）**，其中连片空地 500 个
  —— 可视为「树冠掩膜漏检」的独立估计（量级 3~4%）；
- 需补种面积（336,314 m² 栅格口径）中，距任一树心 ≤2 m 的仅 **2.0%**、≤3 m 的 **6.0%**；
- 而全园有效区的**自然基准**是 ≤2 m **14.5%**、≤3 m **32.9%**
  （树心平均间距只有 8.4 m，任意点本来就在树心附近）
  → **空地落在树心附近的比例只有全园基准的 1/5~1/7**，说明空地确实避开了树。

→ 这条独立证据**支持空地判定主体正确**，残余误报量级约 2%（≈7,000 m²）。

**建议**：
1. **不要用固定绝对阈值 5.2 m**。既然 DSM 被平滑导致低估 40%，可改为
   **局部相对阈值**（如 `CHM > 该瓦片/区块冠层高度的 55% 分位`），
   让"多高算树"随影像自适应 —— 但**必须先做 A/B 验证**，不可直接上线；
2. 对「seg 单独决定」的那 21.5 万 m² **单独打标**（例如 `class_method` 里加
   `evidence=seg_only`），让用户在 ArcGIS 里能一键筛出来复核；
3. 用 `tree_info.json` 做**逐株位核对**（见第 7 节的相位定标），
   它比语义分割更"几何"，是唯一能独立校验"格点在哪"的数据源。

| 6.2 m | 832,701 | −92,482 |
| 7.2 m | 808,134 | −117,049 |

| 否决阈值 veto | 树冠面积 m² |
|---|---|
| 0.6 m | 876,195 |
| 1.2 m（现用） | 863,071 |
| 2.0 m | 850,593 |

→ **core 每动 1 m，约 3.0 万 m²（有效区 2.3%）在"树/非树"之间翻转**。
需补种面积只有 39.9 万 m²，也就是说**阈值动 1 m ≈ 需补种数字动 7~8%**。
而这两个阈值只用 **5 个真值点**标定。

**建议**：
1. 标定点从 5 个扩到 20~30 个（可用 `active_learning.py` 挑"压线样本"来标，
   效率最高 —— 该脚本已写好但从未运行）；
2. 交付时**同时给出敏感性区间**（例如"以 4.7/1.2 计，需补种 ±2.5 万 m²"），
   而不是只给一个点估计；
3. 桌面端把 `elevation_core_chm` / `elevation_veto_chm` 暴露成可调参数（契约里已有），
   并配一个"改参数 → 面积变化"的即时预览。

## 5. 「亮白低饱和」判据的分类缝隙（2,925 m² / 107 块）

**判据**（`landcover.py`）：
- 道路：`L>170 & S<0.20` + **fill < 0.30**（线状）+ 面积 ≥12 m²
- 办公区：同一掩膜 + **fill ≥ 0.30**（面状）+ 面积 **≥400 m²**

→ **fill ≥ 0.30 但面积在 12~400 m² 之间的亮白地物，两个类都不收**，
会原样留在空地候选里 → 被算成需补种。

**实测**（探针 `probe_bright_water.py`，26 cm 网格近似）：

| 亮白地物（L>170 & S<0.20） | 面积 m² | 块数 |
|---|---|---|
| 合计 | 57,297 | 66,083 |

| → 判为 office | 1,723 | 2 |
| → **★缝隙★（fill≥0.30 且 12~400 m²）** | **2,925** | **107** |
| → 噪声（<12 m²） | 15,948 | — |

缝隙里最大的几块：67 / 58 / 57 / 57 / 56 m²（fill 0.31~0.43）。
**目视实例**：第 2 号水塘裁图里那座**泵房**（约 80 m² 的白色屋顶）正落在这个区间。

## 6. 业务模糊带：非树区域 29% 是绿色植被，算法不分「高草 / 幼树」

**实测**（探针 `probe_ambiguous.py`，非树区域按 高度 × 绿度 交叉分档）：

| 高度档 \ 绿度 | ExG<30（裸土） | 30~60（稀疏） | ≥60（绿色植被） | 小计 |
|---|---|---|---|---|
| CHM < 1.2 m | **158,146** | 25,092 | 23,298 | 206,536 |
| 1.2 ~ 3.0 m | 63,864 | 15,101 | **65,764** | 144,729 |
| 3.0 ~ 5.2 m | 21,527 | 14,850 | 33,722 | 70,099 |
| 合计 | 243,536 | 55,043 | **122,784** | 421,363 |

- **明确裸地**（CHM<1.2 且 ExG<30）：**158,146 m²（37.5%）** ← 铁定要补种
- **绿色中高植被**（CHM≥1.2 且 ExG≥60）：**99,486 m²（23.6%）** ← 可能是高草/蕨/幼树，
  **是否补种是业务判断，不是算法能回答的**

10-15 那次对"新增 >1000 m² 的 9 个大块"逐个量过：CHM 中位 **1.04~3.47 m**、
DJI 判非树 71~100% → 结论是"确实不是树，但**不是矮草，而是中等高度植被**"。

**更麻烦的是**：`docs/03-算法教学/DSM高程辅助检测方案.html` 里规划了
「**低矮植被**」独立类别（分层：0.3~1.5 m 草/蕨、1.5~4 m 幼树/灌木），
但 **代码里从未实现**（`grep 低矮植被 scripts/*.py` 只有一句注释）。
而该方案文档的假设"草 0.3~1.5 m vs 油棕 ≥4 m 一刀切开"
**已被项目自己的实测否定**：草地真值点 1 的 CHM 中位是 **3.05 m**
（紧邻油棕，被 DSM 平滑"渗高"），空地真值点 2.32 m。

**建议**（这是本项目**最大的产品级改进点**）：
1. 实现「低矮植被 / 待定」类别（按 CHM 1.2~5.2 m + 绿色），单独成层；
2. 补种清单里把它标成"**待业务确认**"，而不是直接计入需补种；
3. 更根本的：**补种计划本质依赖"这块地什么时候推的、种没种"这个非影像信息**。
   建议桌面端加一个"**人工确认**"字段（可导入补种计划表），算法只负责"哪里可疑"。
4. 若要自动区分"幼树 vs 高草"，需要**多时相**影像（同一地块两期对比）——
   单期影像做不到，不要在这上面继续投入特征工程。

## 7. 种植网格的**方位角合成有「角度别名」bug**（本次最硬的一处代码级缺陷）

**现象**：同一份代码、同一幅影像，两次全量跑估出的网格方位角差 20.5°：

| 跑次 | 株距 | 行距 | **方位角** | 质量 | 勘察采样 |
|---|---|---|---|---|---|
| 10-15 公司机 | 8.35 m | 7.23 m | **0.7°** | 0.734 | 9 探测 / 7 成功 |
| 10-16 本机 | 8.45 m | 7.32 m | **21.2°** | 0.752 | 8 探测 / 7 成功 |

**根因（已定位）**：各瓦片估出的方位角本身是**别名**的 —— 本机日志：
`3.0° / 61.0° / 1.0° / 61.0° / 90.0° / 179.0° / 179.0°`。
等边三角形种植（8.45 m / 错行 60°）的格点具有 **60° 旋转对称**，
所以 0.7° / 59° / 61° / 179° 描述的是**同一个格子**，而 90° 不是。
**直接对这些角度取中位数（`global_consensus`）会得到一个谁都不对的值。**

**真值判定**（探针 `probe_phase_local.py`）：用 `tree_info.json` 的 15,190 个树心，
在 3 个 300 m 窗口内做「方位 0.5° 步长 × 相位 8×8」细扫，
指标 = 树心落在格点 3 m 内的比例（随机基准 **45.8%**）：

| 窗口中心 UTM | 树心数 | 最佳对齐率 | 最佳方位 |
|---|---|---|---|
| (522300, 131400) | 369 | **97.3%** | **59.0°** |
| (522700, 130900) | 1,225 | **79.5%** | **59.0°** |
| (523100, 130500) | 1,222 | **83.1%** | **59.0°** |

→ ① 树心**确实**按 8.45 m 格网种植（对齐率远超随机基准）；
→ ② **真实方位 ≈ 59°（≡ −1°，即公司机那个 0.7° 是对的），本机跑出的 21.2° 错了约 20°。**
（全幅直接细扫不可行：1,500 m 跨度上 0.2° 就漂移 5 m，必须局部判定。）

**后果**：`classify_gaps()` 的核心判据是「质心到最近格点的距离」，
方位角错 20° 会让格点相位系统性偏移 → **类别归属抖动**。
两次跑的实际差异（**总面积逐位一致，只有类别归属变了**）：

| 类别 | 公司机（0.7°） | 本机（21.2°） | Δ |
|---|---|---|---|
| 连片空地 | 489 / 328,999.8 m² | 480 / 327,655.4 m² | −9 块 / −1,344 m² |
| 不确定 | 466 / 40,478.1 | 453 / 39,954.6 | −13 块 / −524 m² |
| 株位空缺 | 283 / 17,421.6 | 286 / 18,105.8 | +3 块 / +684 m² |
| 林间空隙 | 225 / 12,444.7 | 244 / 13,628.5 | **+19 块 / +1,184 m²（+9.5%）** |
| 道路/水体/办公 | 192 / 37,560 | 192 / 37,560 | **0 / 0** ✅ |
| **需补种合计** | **1,463 / 399,344.3** | **1,463 / 399,344.3** | **0 / 0** ✅ |

（掩膜后同样复现 1,437 块 / 376,185 m²、非种植区 26 块 / 23,159 m²、交付包 1,655 要素 / 8 类
—— **本机全链路可复现**，见第 0.1 节。）

**建议**：
1. **方位角合成前先做等价类折叠**（mod 60° 对齐到同一分支，或对 6 个分支投票）再取中位数
   —— 这是本次唯一"改几行就能修"的算法缺陷，优先级高于其它；
2. 用 `tree_info.json` 的**局部细扫**独立定标方位（本次实测 59.0°、对齐率 79~97%），
   作为第二证据与影像反推结果交叉校验；
3. 网格勘察**采样瓦片固定化**（按地理位置均匀取 N 块，而不是按有效性排序取前 N），
   并在结果 JSON 里记录 `survey_tiles` 列表，便于复现；
4. **把 `planting_grid.origin_x_m/origin_y_m` 的参考框架写进文档**：本次实测，
   它既不是 UTM 绝对坐标、也不是"影像左上角 + 偏移"——三种假设下的树心对齐率
   都等于随机基准 46%（探针 `probe_frame.py`）。连项目内部的分析脚本都无法
   直接复用这个网格（`probe_slots.py` 因此失效，无法按株位点数）。

## 9. 遗留的未验证项

1. **非种植区掩膜**：阈值敏感（同一幅影像影响区间 **4%~26%**）；
   `output/forest-mask-争议区.geojson` 里 16 块 / 4.08 ha 是"真·模糊地带"，
   多特征指纹比对结果不干净（密度像森林、CHM 像种植区）；
   ② 掩膜影响面积中约 **9,155 m² 落在 `CHM_P90>13` 的疑似 DSM 伪影区**，正确性不可验证。
2. **没有标注验证集**：全部验证证据 = 5 个真值点 + 目视抽查 + DJI 交叉核对。
   `active_learning.py`（主动学习挑标注样本）已实现但**从未运行**。
   建议真做一轮：挑 30 个压线样本 → 用户标注 → 得到第一份 precision/recall。
3. **CHM 高值区性质**（本次新增实测，供参考）：
   `CHM≥12 m` 共 65,996 m²（有效区 5.1%），其中 `seg=other` 的仅 6,420 m²；
   这些区域的 **5×5 粗糙度中位 0.604**，与健康油棕（0.54~0.71）一致、
   比未开发林核心（0.079~0.091）高一个数量级 →
   **支持"高 CHM 是垂直伪影叠加在真实植被上"的解释**（不是伪影在裸地上造假高度），
   因此"高 CHM 造成漏检"的风险有限（上限约 6,420 m²），
   但**也意味着 CHM 不能用于精细高度分层**（第 6 节的「低矮植被」类别要格外小心）。
