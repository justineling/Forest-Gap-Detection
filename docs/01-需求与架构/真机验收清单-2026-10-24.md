# 真机验收清单 · 2026-10-24

> 给**公司电脑 / 打包版**用。开发机上跑过的（`npm test` / `cargo test` / e2e）不在这里，
> 这份只列"只能在真机、真安装包上验"的项。
>
> 一共 **10 条**，预计 30~40 分钟。每条都写了「怎么判成功」和「失败时抓什么」。
> 建议按顺序做：前 3 条是数据安全（出问题会丢东西），后 6 条是功能。

## 0. 准备（2 分钟）

1. 用 `2. 构建安装包.bat` 出包，装到**干净目录**（不要覆盖旧安装）。
2. 打开 `%LOCALAPPDATA%\fgd\logs\app.log`，先清空或记下当前行数 ——
   后面每条都要对照这个文件。
3. 确认 `data\output\` 里至少有一份结果（跑过一次检测）。

---

## 1. 单实例：双击两次图标

| | |
|---|---|
| **步骤** | 双击桌面图标 → 等窗口出来 → 再双击一次 |
| **预期** | 第二次弹出原生对话框「Forest Gap Detection 已经在运行了」，**没有第二个窗口** |
| **失败时** | 若真的开出两个窗口：截图两个窗口的标题栏 + `app.log` 末尾 20 行 + 任务管理器里 `fgd-desktop.exe` 的进程数 |

> 为什么重要：两个进程会各起一个瓦片服务，并且**同时写 settings.json**，后写的赢 —— 前一个界面显示的影像/结果就和磁盘不一致了。

---

## 2. 配置损坏：手工改坏 settings.json

| | |
|---|---|
| **步骤** | ① 完全退出程序 ② 找到 `data\settings.json`（便携模式在程序目录旁，否则 `%LOCALAPPDATA%\fgd\settings.json`）③ 把最后两个 `}` 删掉 ④ 重新打开 |
| **预期** | ① 界面顶部出现**琥珀色提示条**：「配置文件损坏（…），已改名保留为 settings.json.bad-…」② 需要重新选影像 ③ 同目录下**真的存在**那个 `.bad-<时间戳>` 文件，内容是你改坏的那份 |
| **失败时** | ① 没提示条 → 截界面 ② 找不到 `.bad` 文件 → `dir data\` 的输出 ③ 直接白屏/闪退 → `app.log` |

> 为什么重要：以前是静默重置，用户只会觉得"这软件怎么老让我重选影像"，而原文件其实还在那儿。

---

## 3. 影像挪目录：旧结果不能消失

| | |
|---|---|
| **步骤** | ① 退出程序 ② 把 `WGR17-002.tif` 从 `drone data\` 挪到 `D:\临时\` ③ 打开程序 → 用「⋯ 更多 → 更换影像或结果文件」重新选它 ④ 点工具栏「区块」下拉 |
| **预期** | ① 下拉里那一块**还在**（不是"什么都没有"）② 如果旧路径已失效，它标着「影像不在原位置了」③ 点它 → 正常切过去并载入多边形，**不需要重跑 6 分钟** |
| **失败时** | 下拉为空 / 点进去报"影像找不到" → 截下拉 + `app.log` 里「已切换到区块」那几行 |

> 为什么重要：这是"白跑 6 分钟"的那一类。旧结果 + 复核编辑都挂在它上面。

---

## 4. 区块下拉：跑两块、来回切

| | |
|---|---|
| **步骤** | ① 跑完 block A 的检测 ② 换一张（或同一园区另一张）tif 跑 block B ③ 点工具栏「区块」（显示当前区块名 + ▾）④ 点 A |
| **预期** | ① 下拉里**两块都在**，各自显示「大小 · 高度图 ✓ · 时间」② 当前那块标「当前」且置灰 ③ 点 A → 切过去，地图上是 A 的多边形 ④ `output\` 下**两份** `<区块>-gaps.geojson` 都在（B 没覆盖 A） |
| **失败时** | 只有一块 / 点 A 后地图空白 → 截下拉 + `dir data\output\` 的完整列表 |

> 为什么重要：以前 16 个命令里没有 list，切区块只能重选影像 —— 几十块之后全靠记忆。

---

## 5. 切到"影像已丢失"的区块

| | |
|---|---|
| **步骤** | 承接第 3 条：把那张 tif 改成别的名字（或删掉），再点它那一块 |
| **预期** | 弹出**一句人话**：「区块「…」的影像找不到了：<路径>。它可能被移动或删除。请用「⋯ 更多 → 更换影像或结果文件」重新选择这张影像。」—— 界面**不白屏**、**不静默无反应** |
| **失败时** | 什么都没发生（点了没反应）→ 截界面 + `app.log` |

---

## 6. 老结果名：`wgr17-final-gaps.geojson` 也要能迁

| | |
|---|---|
| **步骤** | ① 退出程序 ② 造一份 `data\output\wgr17-final-gaps.geojson`（把现有结果复制一份改名即可，里面的 `source_image` 仍是 `WGR17-002.tif`）③ 打开程序 |
| **预期** | ① 它被改名成 `wgr17-002-gaps.geojson`（若已存在则**保持原样不覆盖**，并给一句提示）② 提示条里有一句「老结果已按区块改名：wgr17-final-gaps → wgr17-002-gaps」③ **文件一个不少** |
| **失败时** | 名字没变 → `dir data\output\*.geojson` + `app.log` 里「老结果」相关行 |

> 为什么重要：以前只认 `wgr17-desktop` 一个历史名，叫别的名字的老结果**永远**不迁移，用户看到的是"升级后数据没了"。

---

## 7. `jobs` 与 `caches` 并存：缓存要合并，不能成孤儿

| | |
|---|---|
| **步骤** | ① 退出程序 ② 手工造一个 `data\output\jobs\testblk\tiles\1.json`（随便一个 json）③ 打开程序 |
| **预期** | ① 提示条：「缓存目录已合并：1 个区块从 output/jobs/ 搬到 output/caches/（原有内容一个字节都没动）」② `output\caches\testblk\tiles\1.json` 存在 ③ `output\jobs\` 只剩空壳或被删（**只在空的时候**）④ `output\caches\` 里原有的东西一个不少 |
| **失败时** | 文件被删/被覆盖 → 立刻停止操作，把 `output\` 整目录拷出来留存 |

> 为什么重要：以前是"两个都在就什么都不动"，于是旧目录里的瓦片成了孤儿 —— 切到那些区块时 528 块全量重算（几十分钟），界面上没有任何解释。

---

## 8. 高度图归属：生成后应该多一个 `.json`

| | |
|---|---|
| **步骤** | ① 点「⋯ 更多 → 生成高度图与林地边界」跑一次 ② 看 `data\output\` |
| **预期** | ① 出现 `<区块>-chm.tif`（原有的，被重算）② **同时**出现 `<区块>-chm.json` ③ 用记事本打开它，`image_path` 就是你在界面里选的那张 tif 的完整路径，`source_image` 是文件名 |
| **失败时** | 没有 `.json` → `app.log` 里搜「归属元数据」；若有一行「⚠️ 高度图归属元数据没写成功」把后半句错误信息发回来 |

---

## 9. 同名双影像：高度图不能串（最容易漏的一条）

| | |
|---|---|
| **步骤** | ① 准备两个目录：`D:\区块A\WGR17-002.tif` 与 `D:\区块B\WGR17-002.tif`（**文件名一样**，内容可以不一样）② 先选 B → **只点「生成高度图」，不要跑检测** ③ 再选 A 打开 → 看「区块」下拉与检测预检 |
| **预期** | ① A 的区块名是 `wgr17-002-2`（**不是** `wgr17-002`）② A 的预检里「冠层高度模型」是 **warn / 未找到**（或"属于别的影像，已忽略"），**绝不能**是 ok 并指向 B 的那份 ③ 给 A 生成一次高度图后，A 的预检才变成 ok |
| **失败时** | A 的预检显示 ok 且路径是 B 的 → **这就是要抓的 bug**：截预检对话框 + `dir data\output\*.json` + 两份 `.json` 的内容 |

> 为什么重要：这是本项目最贵的一类错 —— 树高整体偏移、结果看着正常、**全程不报错**，只有到现场放样才发现坑挖错了地方。

## 10. 交互修复（2026-10-24 第二轮，浏览器测不到的那几条）

| | |
|---|---|
| **步骤** | ① 启动时出现「发现上次的检测结果」→ 点「换一张影像」→ 在向导里点右上角 **×** ② 再走一次，这次点「重新开始」 ③ 点步骤条第 ③ 步 ④ 从「⋯ 更多 → 检测参数」进来 ⑤ 跑一次**导出** |
| **预期** | ① 弹窗**回到眼前**，地图上的结果**一块没少**，步骤条没跳 ② 弹窗关闭、**不再回来**，圈选范围被清空（步骤条回到第 2 步） ③ 参数窗底部**有「开始检测」** ④ 同一个窗**没有**「开始检测」（只有 ✕） ⑤ 导出成功后**步骤条第 ⑤ 步变绿**、卡片变成「打开输出文件夹」 |
| **失败时** | ① 结果被清空 / 落到第 2 步 → 截步骤条 + `app.log` 里「已取消更换影像」有没有出现 ② 范围还在 → 截状态栏 `ROI：已圈选` ⑤ 第 ⑤ 步仍是「导出交付包」→ 截步骤条 + `app.log` 里导出那几行 |

> 为什么单独列：①~④ 已有 e2e 覆盖（138 项）；**⑤ 是唯一只有代码审查、没有自动测试的一条** —— 浏览器里没有后端，跑不了真导出。所以它必须靠真机这一眼。

## 附：本次改动涉及的 4 个新文件

| 文件 | 作用 |
|---|---|
| `output\<区块>-chm.json` | 高度图归属元数据（几行 JSON） |
| `settings.json.bad-<时间戳>` | 配置损坏时的备份（只在出问题时出现） |
| `output\caches\<区块>\` | 瓦片缓存（旧版是 `output\jobs\`，会自动合并） |
| 工具栏「区块」下拉 | 多区块切换入口（不需要新文件，但界面上是新东西） |
