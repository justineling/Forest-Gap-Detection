## 1. 今天做了什么（五块）

### 1.1 构建链路：补上"产物完整性"这一环

| 改动 | 解决 |
|---|---|
| `ensure_py_runtime` 在时间戳检查后**再跑 `--self-test`** | PyInstaller 中途被打断会留半截 `_internal`（1161/1459 文件，缺 `unicodedata`），但 exe 时间戳是新的 → 旧逻辑照样复用 → 打出 rasterio 不可用的坏包 |
| 补 `if not exist "...desktop_entry.exe" set "FG_PYR_STALE=1"` | 我改 self-test 门槛时把 `goto :epr_ready_silent` 挪出 `if exist` 块外，漏了"缺失"分支 → 跳过重建 → 打出 **2.3 MB** 的空壳包 |

**现在的判定顺序**：存在 → 比时间戳 → 过自检 → 三者都过才复用；任一不过就 `[过期]/[损坏]/[缺失]` + 强制重建。

### 1.2 运行时与外壳

| 改动 | 解决 |
|---|---|
| `desktop_entry.py` / `build_derived.py` 入口 `reconfigure(encoding="utf-8")` | `os.environ.setdefault("PYTHONIOENCODING")` **对当前进程无效** → 打包后 stdout 是管道、默认 cp936 → 「生成高度图」报 `[E4099] charmap` |
| stderr 读取改 `read_until` + `from_utf8_lossy` | `.lines().map_while(Result::ok)` 遇一个非 UTF-8 字节就**整体停止**，traceback 全丢 |
| 关窗拦截（`on_window_event`） | 检测/生成中关窗 → 系统对话框：「继续等待」/「中断并退出」 |

### 1.3 交互打磨 P0（用户反馈）

| 改动 | 之前 |
|---|---|
| 检测前强制确认参数 | 直接用上次参数开跑，用户不知道用的是什么 |
| 进程数按核数推荐 | 固定 4（4 核笔记本过载、32 核工作站浪费） |
| 进度按时间平滑（0.2s 节流） | `progress_every=20` → 528 块只发 20 次 → 每次跳 5% |

### 1.4 交互打磨 P1（工程师实现 + QA 独立审查）

| 改动 | 关键点 |
|---|---|
| 步骤 2「确定范围」不再被跳过 | `blocks: true` + `isStepDone('range')` 含 `detected \|\| hasResult`（跳过跑整幅后自己变绿，不卡死） |
| 主按钮改「圈定范围」 | **QA 抓到的真 bug**：原实现主按钮和「跳过，跑整幅」同 `kind: 'detect'`，两个按钮都只是弹窗，"跳过"没跳过任何东西 |

| 参数窗「上次使用」+ 兜底提示 | 5 个分组各一句「不确定就保持默认」；进程数等于推荐值时标「（已按你的电脑推荐）」 |

### 1.5 两处"看起来像 bug 其实是设计"的澄清

| 现象 | 真相 |
|---|---|
| 导入 tif 没出现"没有加速结构"横幅 | `WGR17-002.tif` **内部自带 6 级金字塔**（`action=none`）。目录里那个 1.1 GB 的 `.ovr` 是另一张图 `WGR17.tif` 的 |
| 重启后界面还有一片空地多边形 | 那是 **内置演示样例**（`sample-gaps.geojson`），后端不可用时自动塞进去的。已改为只在 `?demo=1` 时加载 |

**顺带新增**：状态栏显示当前影像的加速结构来源 —— `加速：内部金字塔 ×6` / `加速：外置 .ovr ×6` / `⚠️ 无加速结构（远处会慢）`。

## 2. 关键设计决定（今天新增）

1. **不做系统托盘**。本项目没有 tray，点 × = 真退出。检测是一次性任务（3~6 分钟）不是常驻服务，托盘会制造"以为关了其实还在跑"的困惑。
2. **检测中切进程数不实时生效**。多进程池启动时创建，改大小要重建池 → 丢已完成瓦片。诚实的做法是"下次检测生效"。
3. **关窗时 `derive` 刻意不杀**（沿用 10-21 的决定）。它正在写 CHM，跑完比留半个好；dialog 里明确告知"会在后台跑完"。
4. **检测输出是原子写入**（`.tmp` → `os.replace`），所以中断不会留损坏 JSON，只有无害 `.tmp` 垃圾。

## 3. ⚠️ 两个坏包事故（我造成的，必须记住）

| 包 | 体积 | 症状 | 原因 |
|---|---|---|---|
| 13:46 | 71 MB | `rasterio` 缺 `unicodedata`，`--self-test` 返回 `ok:false` | **我停掉了正在 PyInstaller COLLECT 的构建** → 半截 `_internal`，但 exe 时间戳是新的 |
| 14:06 | **2.3 MB** | `py-runtime` 目录是空的 | **我上一版补丁的回归**：`if not errorlevel 1 goto` 挪出 `if exist` 块外，漏了"exe 不存在"分支 |

**固化成两条铁律**：
1. **永远不要中途 Ctrl+C 杀正在打包的构建**。
2. **改 `if (...)` 块结构必须穷举分支**（存在 / 缺失 / 过期 / 损坏），并用桩测跑一遍再打包。

**交付前四项检查（以后每次固定执行）**：

```bash

desktop\runtime\desktop_entry\desktop_entry.exe --self-test
# 2) _internal 文件数 ≈ 1459（明显偏少 = 打包被中断过）
find desktop/runtime/desktop_entry/_internal -type f | wc -l
# 3) 安装包 ≈ 71-72 MB（2-3 MB = 没打进 py-runtime）
ls -lh desktop/src-tauri/target/release/bundle/nsis/*.exe
# 4) 阶段 4 日志有 PyInstaller 输出（没有 = 被静默跳过）
```

## 5. 红线（违反会返工）

- **Git**：不自动 commit，必须用户明确同意；提交前 `git reset` 清暂存再按路径 add。
- **算法**：仍封版。除非有真值证据，不要再调阈值。
- **`_环境准备.bat` 不能改名**（所有入口用 `%~dp0` 相对调用）。
- **`desktop/runtime/desktop_entry/.gitkeep` 必须保留**（tauri-build 做存在性硬检查；PyInstaller 会清空目录，打包后要恢复）。
- **`sidecar.py` 的 stdout 是 NDJSON 数据通道**，禁 `print` 污染。
- **Python 脚本入口必须 `reconfigure(encoding="utf-8")`**。
- **界面文案禁术语**：`gdaladdo` / `ovr` / `NDJSON` / `sidecar` / `瓦片` 不许出现在用户可见文字里。
