## 2. 10-22 晚间新增（家机 19:44~20:23，三个提交）

### 2.1 启动时问一句「继续上次结果 / 重新开始」（`4bbd662`）

**用户原话**：「重新构建安装包后 app 还是默认就读取并直接跳转到第四步了，我不希望这样。应该有 1 个弹窗来让用户决定吧」

**根因**：`lib/workflow.ts` 的 `isStepDone('detect')` 写的是 `s.detected || s.hasResult` ——
**磁盘上有历史结果就算"检测已完成"**，于是 `computeSteps` 的 active 直接落到第 4 步。

**三个刻意的不对称设计**（改之前先读）：

1. **ESC / 点遮罩 / 点 × 一律等于「继续复核」**，不是「重新开始」。
   两个动作后果不对称：继续只是"这次先不重跑"，重新开始要重跑 6 分钟才能找回。
2. **「重新开始」只清界面**（`setGaps([])`），**不删磁盘文件** —— 用户可能只是这次不想看。
3. **只在"启动后首次加载"问**。检测完成后的自动刷新（`loadGaps({ rerun: true })`）、
   首次加载失败后重试，都不弹。判定全在 `lib/resume.ts` 的四条布尔规则里，30 条断言覆盖。

### 2.2 四项交互修正（`2af6586`）

| # | 问题 | 根因 | 修法 |
|---|---|---|---|
| 1 | 点「重新开始」后"依然载入并跳到第二步" | `loadGaps` 里**先 `setGaps` 再弹窗** → 启动瞬间地图闪 1,762 块 | 命中弹窗条件时**先不应用**，暂存 `pendingResume`，用户选完再 `setGaps` |
| 2 | 参数改乱了没法回默认 | 只有逐项 `setParam` | 参数窗加「恢复推荐值」，写回 `DEFAULT_DETECT_PARAMS` |
| 3 | 右下角「下一步」卡片压住地图 +/− | `NavigationControl` 也在 `bottom-right` | **挪控件到 `top-right`**，卡片不动 |
| 4 | 状态栏太矮、面板宽度不能调 | 尺寸写死在 CSS | 三个拖拽手柄 + CSS 变量；**刻意不记忆** |

**问题 1 里藏着一个会让修复完全失效的 bug**（工程师挖出来的，值得记住）：
dev 下 `React.StrictMode` 会跑两遍启动 effect，第二次 `loadGaps` 的 `firstLoad` 已是 false
→ **绕过弹窗直接应用**。而**打包版没有 StrictMode，看着完全正常** —— 典型的本地假绿。
现在用 `resumePending` ref 当闸门：有一份在等确认时，后续 `loadGaps` 只记日志、不应用。

**问题 2 的一个细节**：`workers` 必须**重新调 `recommendWorkers()`**，不能沿用常量 ——
常量是模块加载时算的一次，换机器/改分辨率后沿用旧值就与"按这台电脑推荐"自相矛盾。

**问题 3 的判断**（与用户建议不同，已说明理由）：用户说"卡片可以放右上角"，
实际改的是**挪缩放控件**。卡片是主行动入口，应留在阅读动线的落点；
挪 30×60 的控件比挪 330px 的卡片风险小得多。连带：顶部横幅改成"右侧留 62px 安全区"居中，
否则窄地图下横幅会横向盖住右上角控件（横幅 z-index 更高，+/− 就点不到）。

**问题 4 的实现要点**：
- CSS 变量 `--left-w / --right-w / --status-h` 驱动网格
- Pointer Events + `setPointerCapture`（`mousedown/mousemove` 拖出窗口会丢事件）
- 钳制抽成 `lib/layout.ts` 纯函数：左 200~480 / 右 220~520 / 状态栏 64~320，
  还有"窗口变窄时左右面板一起收，保证地图 ≥360px"（35 条断言）
- **尺寸刻意不写 localStorage**（用户明确要求每次回默认）。代码里在这几个 state
  上方写了注释说明这是刻意的，**否则下一个人会"顺手"补上持久化**。

## 6. 红线（违反会返工）

- **Git**：不自动 commit，必须用户明确同意；提交前 `git reset` 清暂存再按路径 `add`。
- **算法**：仍封版。除非有真值证据，不要再调阈值。
- **`_环境准备.bat` 不能改名**（所有入口用 `%~dp0` 相对调用）。
- **`desktop/runtime/desktop_entry/.gitkeep` 必须保留**（tauri-build 做存在性硬检查；PyInstaller 会清空目录，打包后要恢复）。
- **`sidecar.py` 的 stdout 是 NDJSON 数据通道**，禁 `print` 污染；人类日志走 stderr。
- **Python 脚本入口必须 `reconfigure(encoding="utf-8")`**（`os.environ.setdefault` 对当前进程无效）。
- **界面文案禁术语**：`gdaladdo` / `ovr` / `copy` / `inplace` / `GDAL` / `NDJSON` / `sidecar` / `瓦片`
  不许出现在用户可见文字里。`tests/overview.test.ts` 有源码级守卫（含守卫自检）。
- **`if (...)` 块内的 echo 文本禁用 ASCII 括号**（提前闭合代码块，症状可以是"if/else 双双执行"）。
- **HTML 报告必须同时出「专业版 + 小白版」**；含图 HTML 内联 base64/SVG，禁相对路径。
- **历史文档纠错不改正文**（顶部加提示块 + 文末后记）。

### 12.2 五个教训（都是当天踩出来的）

**1. early return 不能出现在任何 hook 之前** ← 最贵的一课

```tsx
if (input.detectRunning) return null   // ← 我加在这里
const action = nextAction(...)
useEffect(...)                          // ← 家机原有的 effect，在它后面
```

检测开始时组件从 3 个 hook 变 2 个 → `Minified React error #310` → **整块白屏**。

**任何 `return` / `return null` 都必须放在所有 hook 之后。**
判断方法：改完组件 grep 一遍 `useState|useEffect|useMemo|useAppStore` 的行号，
确认全在 `return` 之前。

**2. `npm test` 抓不到渲染错误**

项目的 `npm test` 是纯单元测试（`tests/*.test.ts`），**不渲染组件** →
hook 顺序、props 类型、JSX 运行时错误一律抓不到。
`tsc` 也只做类型检查。

**目前没有任何自动化手段能发现"组件渲染崩了"** —— 这是已知缺口。
用户已同意补「组件级渲染冒烟测试」，但**今天没做**（要下班）。见 §12.4。

**3. `config_path()` 在 data 的上一级**

`%LOCALAPPDATA%\fgd\settings.json` —— **不在 `data/` 里**。
任何"迁移数据目录"的代码都要注意这个位置差异，否则 settings 会留在原地。

**4. 家机的 `shouldClearGapsOnImageChange` 语义与用户诉求相反**

家机的规则是"同一张影像 → 不清"（防止重选时误抹结果），注释里还标了 ★。
但用户的实际路径是「点换影像 → 又选同一张 → 期望重新开始」。
**产品口径以用户实际操作为准**，不能只看代码注释里写的理由。

**5.1 数据目录搬迁时，`settings.json` 里的绝对路径不会自己变**

`migrate_from_localappdata` 只**复制文件**（`settings.json` + `output/`），
不改其中的路径。于是：

```
settings.json 里： "gaps": "C://Users//kyling//AppData//Local//fgd//data//output//wgr17-desktop-gaps.geojson"
实际文件在：        D://Forest Gap Detection\data\output\wgr17-desktop-gaps.geojson
```

向导显示「✓ 结果文件」（它只显示文件名），点「开始使用」→ `set_data_paths`
校验 `exists()` 失败 → **卡在第一步**（2026-10-23 用户实测）。

**修法**：`rebase_to_data_root(old)` —— 拿文件名去数据根下的 `output/` 和根目录
各找一次，找到就返回新绝对路径（只改路径、不搬文件）。
接入两处：`load_config()`（读出来自愈并写回）、`set_data_paths()`（前端传旧路径时兜底）。

**推论**：任何"把数据换个地方"的迁移，都要问一句
**"配置文件里的绝对路径谁来更新？"** —— 只搬文件是不够的。

**5.2 `explorer.exe` 不认 `\\?\` 前缀 —— 会静默退化成打开父目录**

`bundled_data_root` 的便携分支返回的是 `\\?\D://...//data`（Rust 的
`canonicalize` / Tauri 的 `resource_dir` 都会产生这种形式）。
`open_path` 原样交给 explorer：

```rust
cmd.arg(target.as_os_str());   // \\?\D://Forest Gap Detection\data
```

结果**打开的是 `D://Forest Gap Detection`**（父目录），不报错、只是"差一级"。

修法：`strip_long_prefix_str()` 剥前缀（`\\?\UNC\server\share` 还原成
`\\server\share`），`open_path` 与 `bundled_data_root` 两处都剥。

**推论**：凡是把路径交给**外部程序**（explorer / 编辑器 / 命令行工具）的地方，
都要先剥 `\\?\` —— 这类失败不会报错，只会"行为差一点"，最难发现。

**5. 我的执行环境有 `node-safe-delete-shim`（只影响 AI，不影响用户）**

它会拦截 `fs.rmSync` 并重定向到回收站 → vite 构建前清 `dist` 时失败：

```
at trashViaBinary (...node-safe-delete-shim.cjs:300:15)
at emptyDir (vite/.../dep-BK3b2jBa.js:17082)
```

**绕过**：打包前先 `rm -rf desktop/dist`（Bash 的 `rm` 不走这个 shim）。
**用户自己双击 `2. 构建安装包.bat` 不会遇到。**

### 15.2 改之前会怎样（这是"漏洞"本身）

| 产物 | 路径 |
|---|---|
| 结果 | `output/<job>-gaps.geojson` |

### 15.4 我复核时抓到的洞（已修）

新增 `scripts/test_block_jobs.py`（28 项，进 `--fast` 第 12 层），含**两条反证**

被仓库里历史结果（`wgr17-final-gaps.geojson`，`source_image` 恰好也是 `WGR17-002.tif`）污染。

## 18. 高度图归属元数据：把最后一个"数字自洽的错答案"堵掉（2026-10-24）

用户点名要修 §17.8 那一条。它不在审计 A~G 里，但性质一样：**不报错、数字自洽**。

### 18.1 洞的形态（一句话）

> A/B **同名**影像，B **只生成过高度图、没跑过检测** → A 用上 B 的树高。

为什么 A~G 修完它还在：

| 判据 | 这个现场成立吗 |
|---|---|
| `output/<job>-gaps.geojson` 存在？ | ❌ B 没跑过检测 |
| `output/caches/<job>/` 存在？ | ❌ B 没跑过检测 |
| 那就看 `output/<job>-chm.tif` | ⚠️ 存在，但**没有任何归属信息** |

于是区块名分配算出的还是同一个名字，A 直接挂上 B 的高度图。

### 18.2 修法：让高度图自己说"我属于谁"

`scripts/build_chm.py` 写完 tif **之后**（顺序不能反，见注释）补一份同名 `.json`：

```json
{
  "schema": "fgd-chm/1",
  "source_image": "WGR17-002.tif",
  "image_path": "D:/data/drone data/WGR17-002.tif",
  "created_at": 1761...
}
```

- 文件名规则：**后缀换成 `.json`**（`wgr17-002-chm.tif` → `wgr17-002-chm.json`）。
  Python 是 `Path.with_suffix(".json")`，Rust 是 `Path::with_extension("json")` ——
  两边必须一致（不一致就等于没写，而且**不会报错**）。
- 原子写（`.part` + `os.replace`）；写失败只记一行日志、返回 `None`，
  **绝不**因为元数据失败让已经算好的 42 秒高度图白费。
- `image_path` 记 `os.path.abspath`（不解析符号链接，与 Rust `same_file_path` 同语义）。

### 18.3 三处读它（缺一处这个洞就还在）

| 位置 | 作用 | 行为 |
|---|---|---|
| `job_slot_is_free` | 区块名分配 | 高度图元数据说属于**别人** → 这个槽位算占用 → 拿 `-2` |
| `preflight_core` | 检测前最后一道门 | 找到的 chm 属于别人 → `warn` + **不回填** `chm_path`，并说明"已忽略，请重算" |
| `usable_chm`（`set_data_paths` / `switch_block`） | 切区块 | 别人的 chm 不挂上，界面提示"检测前请先生成高度图" |

另外 `chm_meta_image` 还兼了一个用途：**迁移时定区块名**。
"只生成过高度图、没有结果、配置里也没影像"的现场，以前只能靠
`job_from_existing_results`（"磁盘上只有一份"）瞎推；现在这份元数据直接说了。

### 18.4 一个必须保留的退化：没有元数据 → 照用

老高度图（升级前生成 / 从 `chm.tif` 迁过来）没有 `.json`。
如果"存在但判不出归属"就按占用处理，会连环踩两个坑：

1. **无限换名**：生成拿到 `a` → 检测看到 `a-chm.tif` 判"占用" → 拿 `a-2` →
   找不到 `a-2-chm.tif` → 提示缺高度图 → 再生成写 `a-2` → 又看到它 → `a-3`…
2. **迁移白做**：`migration_completes_half_done_migration` 要求"迁移后
   `job_id_for_output` 仍算出同一个区块名"，否则刚迁好的 `<job>-chm.tif`
   立刻被算成别人的，用户白等 42 秒重算。

所以规则是：**明确是别人的**才算占用，判不出就放行。这个洞因此只对
"新生成的高度图"彻底关闭 —— 而新生成的一定带元数据。

## 19. 交互缺陷：一个「×」把结果清空了（2026-10-24 下午）

### 19.1 用户原话

### 19.2 根因（一行）

**"关闭"这个手滑高发动作，被赋予了破坏性副作用。**

### 19.3 两轮共修 6 条

| # | 修之前 | 修之后 |
|---|---|---|
| 1 | 点「换一张影像」就清结果；向导点 × 后落到第 2 步 | 只导航，不清任何东西；向导 ×/Esc = 取消，**续跑弹窗自己回来**（渲染条件 `resumeAsk && !wizard`） |
| 2 | `onWizardDone` 的 B2 分支依赖第 1 条顺手清 resume 状态 | 改为在 `onWizardDone` **顶部**清（提交才算做了决定） |

| 4 | 点步进器第 ③ 步只开参数窗，窗里**没有「开始检测」** | `openSettings('detect')` + 关闭时 `closeSettings()` 复位 `'edit'`（「更多 → 检测参数」显式传 `'edit'`） |
| 5 | `ResumeDialog` 的 Esc 只 `preventDefault` → 全局 Esc 仍清选中 | capture 阶段 + `stopPropagation`（与 `WelcomeWizard` 一致） |

1. 五步各自的**进入条件**（对应 `lib/workflow.ts` 的 `isStepDone`）、**退出条件**、

2. **每个弹窗/浮层的 × / Esc / 点遮罩** 语义（6 个，逐个读码确认，不猜）。

### 19.5 三条测试方法教训（比这 6 条修复更值钱）

1. **A/B 对照是唯一能证明"测试有鉴别力"的手段**。把 HEAD 旧代码复制到临时目录另起端口
   跑同一套脚本 → **23 项红**。每条绿都有对应的红作对照，否则"写了条永远绿的断言"
   和"没写"是一样的。
2. **测状态机 ≠ 测接线**。`exported` 那条：单测把 `exported: true` 喂给 `computeSteps` 全绿，

### 20.1 布局（唯一结构性改动）

地图列（flex column）

### 20.3 四条硬坑（都写进代码注释了，别重踩）

**① `display:none` 会让文本从 `innerText` 里消失 → 折叠日志不能用它**

用 `display:none` 藏旧日志行时，`verify_render` 里 12 处"日志里出现过某句话"的断言
**全部假失败**（实测场景 12「导出完成」直接红）。
修法：`max-height` + `overflow:hidden`（元素还在，`innerText` 还在）。

**② 布局层（`styles.css`）写 `display` 会被设计层（`ark.css`）覆盖**

```css
/* styles.css */
@media (max-width: 760px) { .tb-brand { display: none } }   /* ← 无效 */
```

`ark.css` 后 import 且同样单类名，`.tb-brand { display: flex }` 胜出。
**布局相关的 `display` 必须写进 ark.css**（或提高特异性）。

**③ MapLibre 只监听 window resize，不监听容器**

命令条收起/展开、侧栏折叠都会改容器高度 → 必须补：

```ts
new ResizeObserver(() => map.resize()).observe(container)
```

否则 canvas 被拉伸，**影像与矢量多边形错位**（看起来像"检测结果偏了"）。

**④ 每行独立 grid 的 `auto` 列宽逐行不同**

复核行是"每行一个 grid"，`auto` 列会按各自内容算宽 → 类别名在每行 x 位置都不一样。
**面积列必须定宽**（88px）。

补充两条小的：

- `repeat(5,1fr)` 配 4 个按钮会多出一条空列（看起来像"第五个按钮加载失败"）。
- `.panel-head.tabs .tab-n` 特异性高于 `.tab-n`，圆角归零必须用同样选择器。

### 20.4 两处**有意偏离**（别"顺手改回去"）

**① `DetectBar` 组件没删，而是搬进命令条槽位**

看起来"进度条应该并在命令条里，组件可以删了"——**不能删**：

- `verify_render` 有 **8 条断言**挂在 `.detect-bar / .running / .db-track / .db-fill` 上；
- 其中「检测态下 `.next-card` 与 `.next-pill` 都不在」**正是 React #310（hook 顺序）的回归网**，
  而那个 bug 的触发条件就是 `NextStepCard` 在检测中提前 `return null`。

**删组件 = 删网。** 现在位置变了、语义没变，8 条断言原样通过。

**② "已复核下沉"用 `edited` / `source === 'manual'` 判定**

不新增"已看过"持久化状态 —— "看过没改"与"没看过"**数据上不可区分**，
硬做的进度条不可信。

### 20.5 三轮修复（10-25 当天）

**第一轮 · UI 走查 3 条**（CDP 实测 5 个分辨率）

| 缺陷 | 实测数字 | 修法 |
