一、你必须提供的文件

只有第 1 项是硬性要求。另外 3 项决定结果「准不准」，不是「能不能跑」。

文件必需性缺了会怎样（实测量级）放哪 / 怎么给
正射影像
*.tif		 必需 无法检测。程序只会显示「请选择影像」。 任意位置，在首次引导或「⋯ 更多 → 更换影像」里选。
参考：WGR17-002.tif 4.7 GB / 47,130×44,686 px / 3.3 cm/px / EPSG:4326
冠层高度模型
chm.tif		 强烈建议 退化纯 RGB：水塘从 21 块掉到 2 块；未开发林 0 块（本应剔除 25 块）。 它提供「多高才算树」的第二道判据。 优先级（自动探测，不用手填）：
① 影像同目录
② 影像目录下的 output/
③ 数据根 %LOCALAPPDATA%\fgd\data\
④ 数据根下的 output/
检测前会预检并提示缺哪一项。
语义分割结果
segment.tif		 强烈建议 水塘识别率从 98% 掉到 7.9%（含藻类的绿水塘不满足「蓝 > 绿 > 红」的 RGB 规则）。
森林掩膜
forest-mask*.geojson		 强烈建议 未开发天然林被算成「可补种」，实测多出 221 个放样点——现场会挖到不该挖的地方。
检测范围
*.kml / *.geojson		 可选 不导入就跑整幅：约 6 分钟；圈定后只跑圈内：约 3 分钟，且圈外天然林、邻园天然被排除。 「下一步」卡片的「导入 KML」/「手绘范围」。
KML 里的高程（lon,lat,alt）会被自动剥掉；多个多边形取面积最大的那个。
树心表
tree_info.json		 仅重建掩膜 不影响日常检测。只有重新生成森林掩膜（build_forest_mask.py）时才需要。 大疆智图「果树模式」的输出，放在影像同目录。

⚠️ 一个真实的踩坑记录（2026-10-19）

打包版的数据目录 %LOCALAPPDATA%\fgd\data\output\ 是空的。 用户选了仓库里的影像，但 CHM / 掩膜在仓库的 output/ 里， 不在数据根里 → 检测跑出来 water 只有 2 块、undeveloped 0 块。 界面上看起来一切正常，只是数字偏了。 把这两个文件复制到数据根的 output/ 再重跑即可。

四、检测结果：{job}-gaps.geojson

文件名里的 {job} 由任务名决定，桌面端固定是 wgr17-desktop， 所以产物叫 wgr17-desktop-gaps.geojson。它既是界面展示的数据源，也是导出交付包的输入。

字段内容
features[]1,762 个多边形。每块带 gap_id / class / area_sqm / class_confidence / class_reason / node_distance_m
params本次实际用的参数（含 elevation_core_chm / elevation_veto_chm / workers），一页报告从这里读
planting_grid株距 8.45 m / 行距 7.32 m / 方位角 / UTM 原点。放样点位靠它逐株对齐
summary.by_class8 类计数：连片空地 420 · 株位空缺 342 · 不确定 540 · 林间空隙 293 · 道路 116 · 办公 49 · 水体 2 · 非种植区 0
summary.by_priority三档业务口径：确定需补种 / 待复核 / 无需补种 / 不可种植

为什么不是顶层 features

整幅结果把要素放在 blocks[].gaps 下，顶层没有 features。 前端读取时会自动展开两条路径 —— 直接按顶层 features 读会得到空数组，这个坑踩过。

谁该拿哪个文件

给谁发这个为什么
主管 / 甲方补种勘察一页报告.html一页纸：口径、株数、Top 20 大斑块、人工留痕。可打印成 A4 PDF。
现场施工planting-points.csv 或 .kml3,691 个坑位坐标。CSV 进手簿/GPS；KML 进手机导航。
GIS / 测绘gaps-all-utm49n-shp.zipUTM 49N 投影，ArcGIS / QGIS 里量距、出图不会变形。
归档 / 审计gaps-edited.csv记录哪几块是人工改的、原判是什么，事后能追溯。
只想在地图上看gaps-all.kml拖进 Google Earth / 奥维即可，不用装 GIS。

空间规划建议

一套完整数据约 6 GB（影像占 96%）。跑多套数据时，把影像放外接盘、只把 chm.tif / segment.tif / forest-mask 放在数据根，也能正常检测 —— 影像路径由界面选择，不要求在数据根里。
