一、你必须提供的文件

严格说只有 3 个源文件。CHM 与森林掩膜不用你准备 —— 程序会从 DSM 算出来 （这一点以前的文档写错了，2026-10-19 更正）。

文件必需性缺了会怎样（实测量级）放哪 / 怎么给
正射影像
*.tif		 必需 无法检测。程序只会显示「请选择影像」。 任意位置，在首次引导或「⋯ 更多 → 更换影像」里选。
参考：WGR17-002.tif 4.7 GB / 47,130×44,686 px / 3.3 cm/px / 4 波段 / 6 层金字塔
⚠️ 这里的 4.7 GB 与 6 层金字塔是本项目建的：原始下载体积约 3.5 GB、无内嵌金字塔， 2026-10-17 跑了一次 tile_server.py --build-overviews（174 秒）后 被就地写入文件内部（+1.2 GB）。详见 desktop/README.md 坑 3。
语义分割
segment.tif		 强烈建议 水塘识别率从 98% 掉到 7.9%（含藻类的绿水塘不满足「蓝 > 绿 > 红」的 RGB 规则）。 优先级（自动探测，不用手填）：
① 影像同目录
② 影像目录下的 output/
③ 数据根 %LOCALAPPDATA%\fgd\data\
④ 数据根下的 output/
检测前会预检并提示缺哪一项。
地表高程 DSM
dsm.tif		 强烈建议 算不出 CHM → 退化成纯 RGB：水塘 21→2 块、未开发林 0 块。
检测范围
*.kml / *.geojson		 可选 不导入就跑整幅：约 6 分钟；圈定后只跑圈内：约 3 分钟，且圈外天然林、邻园天然被排除。 「下一步」卡片的「导入 KML」/「手绘范围」。
KML 里的高程（lon,lat,alt）会被自动剥掉；多个多边形取面积最大的那个。
树心表
tree_info.json		 仅重建掩膜 不影响日常检测。只有重新生成森林掩膜时才需要。 大疆智图「果树模式」的输出，放在影像同目录。

程序自己算出来的两个文件（不用你准备）

产物谁生成说明
chm.tif
冠层高度模型		 scripts/build_chm.py 从 dsm.tif 算：最小值滤波估出地面高程（DTM），再用 DSM 减 DTM 得到树高。 窗口 30 m，尖峰抑制 4 m，水面自动排除。
CLI：--dsm --segment --ortho --out output/chm.tif
chm.json
高度图归属元数据		 scripts/build_chm.py 跟着高度图一起写出的几行 JSON：这份高度图是从哪张正射影像算出来的 （image_path + source_image）。
桌面端靠它区分「同名但不同目录的两张影像」—— 没有它时，两张同名影像可能共用一份树高， 结果看着正常、高程全错。删了不会坏，只是切区块时判不出归属（会提示重算）。
文件名规则：把高度图的后缀换成 .json（wgr17-002-chm.tif → wgr17-002-chm.json）
forest-mask-*.geojson
森林掩膜		 scripts/build_forest_mask.py 从 chm.tif + tree_info.json + 影像算： 按 100 m 区块统计树心密度，油棕种植区 110~160 株/ha、未开发林 20~60 株/ha， 低于阈值且连片的划为「非种植区」。
CLI：--chm --tree-info --ortho --out output/forest-mask.geojson

✅ 界面里可以直接生成（2026-10-19 起）

「⋯ 更多 → 生成高度图与林地边界…」一步完成两步（约 1 分钟，本项目实测 42 秒）： 先出 chm.tif，再出 forest-mask.geojson， 直接写进数据根的 output/，之后的检测自动用上。
命令行仍可用（scripts/build_derived.py）， 但现场用户不需要碰它。生成完记得重跑一次检测 —— 旧结果是用旧高度图算的。

四、检测结果：{job}-gaps.geojson

文件名里的 {job} 由任务名决定，桌面端固定是 wgr17-desktop， 所以产物叫 wgr17-desktop-gaps.geojson。它既是界面展示的数据源，也是导出交付包的输入。

字段内容
features[]1,762 个多边形。每块带 gap_id / class / area_sqm / class_confidence / class_reason / node_distance_m
params本次实际用的参数（含 elevation_core_chm / elevation_veto_chm / workers），一页报告从这里读
planting_grid株距 8.45 m / 行距 7.32 m / 方位角 / UTM 原点。放样点位靠它逐株对齐
summary.by_class8 类计数：连片空地 420 · 株位空缺 342 · 不确定 540 · 林间空隙 293 · 道路 116 · 办公 49 · 水体 2 · 非种植区 0
summary.by_priority三档业务口径：确定需补种 / 待复核 / 无需补种 / 不可种植

为什么不是顶层 features

整幅结果把要素放在 blocks[].gaps 下，顶层没有 features。 前端读取时会自动展开两条路径 —— 直接按顶层 features 读会得到空数组，这个坑踩过。

空间规划建议

一套完整数据约 6 GB（影像占 96%）。跑多套数据时，把影像放外接盘、只把 chm.tif / segment.tif / forest-mask 放在数据根，也能正常检测 —— 影像路径由界面选择，不要求在数据根里。
