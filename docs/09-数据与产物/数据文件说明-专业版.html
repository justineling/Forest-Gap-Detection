安装目录 D:\Forest Gap Detection 里那些 geojson / tif / jobs 到底是什么
2026-10-23 ｜ 以本机实际文件为准（体积、块数均为实测）

一句话：同一个结果有三种形态 —— 界面上看的「内部结果」、重跑时省时间的「缓存」、 交给 ArcGIS 的「交付包」。它们长得像，用途完全不同，混用会出问题。

1. 数据流：一份影像怎么变成交付包

① 正射影像 drone data\WGR17-002.tif
4.66 GB，你自己提供
→
② 中间产物 output\chm.tif
output\forest-mask-*.geojson
从 DSM / 树木清单派生
→
③ 瓦片缓存 output\jobs\<job>\tiles\*.json
528 个瓦片的中间结果
→
④ 内部结果 output\wgr17-desktop-gaps.geojson
界面读它、你编辑它
→
⑤ 交付包 …\output\desktop-export\
20 个文件，给 ArcGIS

注意 ②③ 都是可再生的：删掉不影响正确性，只是下次要重新算。 ④ 是你的人工编辑成果（删了误报、改判类别都在里面），删了就没了。 ⑤ 是最终交付物，可以随便拷走。

2. data\output\ 逐文件说明

文件体积是什么谁在用 / 删了会怎样
chm.tif 60 MB 高度图（冠层高度模型）。每个像素一个"高出地面多少米"的值。 检测时用来区分「高的是树」和「矮的是空地」。
可再生：⋯ 更多 → 生成高度图与林地边界，约 42 秒。
缺了它会退化成纯 RGB 判断 → 水塘、幼林容易误判。
forest-mask-50m-exg60.geojson 1.4 MB 林地掩膜：用 50 m 网格 + ExG 阈值圈出"哪些地方是已开发的种植园"。 检测时把未开发天然林排除在外 —— 否则天然林里的空隙会被当成"该补种的空地"。
可再生：同上面那个菜单项一起生成。
文件名里的 50m / exg60 是当时的参数，改参数会生成新名字。
wgr17-desktop-gaps.geojson 25 MB
1,726 块		 当前检测结果（内部格式）。界面读的就是它，你的删除 / 改判也写回它。 别删：这是你的工作成果。
结构是 blocks[0].gaps（按"作业块"嵌套）， 不是标准 GeoJSON 的 features —— 所以 ArcGIS 直接导入会失败，见 §5。
_archive\wgr17-final-gaps.geojson 14.5 MB
1,762 块		 10-19 那一轮的旧结果（带 ROI 裁剪）。 程序不读它，已移进 _archive\ 并附 README。
确认不需要对照历史后，整个 _archive 可以删。
jobs\wgr17-desktop\grid-survey.json 3 KB 网格标定审计：每个瓦片采样出的株距 / 行距 / 方位角 / 密度，外加"设计密度 vs 估计密度"检查。 排查「为什么放样点位看着偏了」时用它，是诊断证据。
可再生：下次检测会重写。
jobs\wgr17-desktop\tiles\*.json
528 个，共 8.8 MB		 8.8 MB 瓦片缓存：每个 2048 px 瓦片的检测中间结果，带一个参数指纹。 重跑时若影像与参数都没变，直接复用（实测 322 个 done + 206 个 skipped），省几分钟。
可再生：删掉只是下次全量重算，结果不会变。
指纹不一致的瓦片会自动失效重算，不需要你手动清。

关于 jobs\：为什么它看起来"没用"却一直存在
它只服务于两件事：重跑加速（瓦片缓存）和事后查账（网格标定）。 界面不会展示它，所以你感觉没用到它 —— 这是正常的。它不会越滚越大： 同一个 job 名只保留一套缓存，参数变了旧瓦片会被指纹判死并覆盖。

3. 交付包：desktop-export\

位置：py-runtime\desktop_entry\output\desktop-export\。 为什么在 py-runtime 下面：导出的默认目录是"程序目录下的 output\desktop-export"， 而安装版里程序目录就是 py-runtime\desktop_entry。想放到别处，在导出对话框里改目标目录即可。

文件用途
gaps-all-wgs84.geojson
gaps-all-utm49n.geojson		 全量空地的标准 GeoJSON，两种坐标系各一份（经纬度 / UTM 49N）。ArcGIS、QGIS 直接拖进去就能用。
gaps-all-wgs84-shp.zip
gaps-all-utm49n-shp.zip		 Shapefile 压缩包（含 .prj 投影文件）。老 ArcGIS 工作流、给测绘同事时用这个。
gaps-all.kml 给 Google Earth / 奥维互动地图看的。手机上也能打开。
by-class\gaps-<类别>-utm49n-shp.zip
本次 7 个（有几个类别就有几个）		 按类别分包：只想要"道路"或只想要"待复核"时，单独拿一个包，不用在大表里筛。
planting-points-*
2 GeoJSON + 2 Shapefile + 1 KML + 1 CSV		 放样点位（每一株该种在哪）。由 Python 逐格排坑算出，和界面上看到的一致。
结果里没有种植规格时会整组跳过。
gaps-edited.csv 纯表格：编号 / 类别 / 面积 / 中心经纬度 / 是否人工改过。给不装 GIS 的人看。
补种勘察一页报告.html 一页纸：三类（确定要补 / 待复核 / 不需要）的块数与面积。可以直接打印或转 PDF 交上去。

本次实测 20 个文件 = 13 个顶层 + 7 个按类别分包（结果里有 7 个类别）。 换成 8 个类别就是 21 个 —— 文件数会随数据变，导出对话框里的预览就是按这个规则算的。

4. 为什么内部结果和交付包不能合并成一套

对比项内部结果
output\*-gaps.geojson		交付包
desktop-export\*
数据结构blocks[0].gaps（按作业块嵌套）标准 features 数组
坐标系只有 WGS84，crs 是字符串WGS84 + UTM 49N 双份
附带信息置信度、判定依据、网格单元等内部字段只留交付需要的字段
能被 ArcGIS 直接打开不能（找不到 features）能
为什么需要它界面要按块管理、要支持人工编辑与撤销对方要能直接拖进 GIS 干活

最常见的坑：把 output\wgr17-desktop-gaps.geojson 拖进 ArcGIS → 报"没有要素"。 不是文件坏了，是格式不对。要给别人一律用 desktop-export\ 里的 gaps-all-wgs84.geojson（或 Shapefile 包）。

5. 另外两个常见困惑

5.1 为什么导出目录在 py-runtime 下面，而不是 data 下面？

导出默认写到「程序目录 / output / desktop-export」。 安装版里程序目录是 py-runtime\desktop_entry，所以就在那儿。 这不是 bug，但确实不直观 —— 建议在导出对话框里把目标目录改成 D:\Forest Gap Detection\data\desktop-export，以后所有交付包都在一处。

5.2 chm.tif 和 forest-mask 算"输入"还是"输出"？

对检测来说是输入（检测读它们）；对你来说是输出（程序从 DSM / 树木清单算出来的）。 所以它们放在 output\ 里，但可以随时重新生成。真正的"只进不出"的输入只有那个 4.66 GB 的正射影像（以及可选的 DSM / 地物分类图 / 树木清单）。

6. 清理建议

想清的东西能删吗代价
_archive\能失去 10-19 那轮 1,762 块结果的对照副本。
jobs\<job>\tiles\能下次检测全量重算，多花几分钟；结果不变。
chm.tif / forest-mask-*能检测前要重新生成（约 42 秒），否则精度下降。
*-gaps.geojson（当前结果）别删人工编辑全部丢失，要重跑 6 分钟且改判回不来。
desktop-export\能交付物丢了，重新导出一次即可（几十秒）。
