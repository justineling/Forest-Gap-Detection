结论先行：GeoJSON 文件没有坏。几何实测完全正常——ring 闭合、88 个顶点、宽高比 1:1， 跨度 0.01315° × 0.01318° ≈ 1463 m × 1457 m。

对照组：KML 在 Google Earth 里一定正确，因为 KML 规范强制 lon,lat,alt 且强制 WGS84，无任何歧义。

二、根因诊断：为什么 GeoJSON 在 ArcGIS 里变成「一堆直线」

诊断已确认，问题分三层，全部有实测依据：

  1. 影像与几何本身都没问题。TIF 是 EPSG:4326，有正确的地理配准；GeoJSON 几何实测正常： ring 闭合、88 个顶点、宽高比 1:1、跨度 0.01315°×0.01318° ≈ 1463 m × 1457 m。
  2. ArcGIS 的 GeoJSON 导入器忽略顶层 crs 成员，按「未知平面坐标系」处理—— 经纬度数值被当成了平面坐标 (X, Y)。
  3. 于是 1,048 个多边形被放进 X = 111.197 ~ 111.210、Y = 1.177 ~ 1.190 的 0.013°×0.013° 小方块， 而 TIF 在正确的地理位置。两者相距十万八千里，1048 个多边形挤成极小一坨—— 放大之前，每个地块在屏幕上不足一个像素，看起来就是「一堆直线」。

五、具体操作步骤（照着点鼠标即可）

🚀 路线 A · 最省事，零手动指定坐标系 推荐
  1. 解压 gaps-all-utm49n-shp.zip，把 gapsutm.shp 连同 .shx / .dbf / .prj / .cpg 四个伴生文件解到同一个文件夹（缺一不可）。
  2. 先加影像：Add Data 选 WGR17.tif（3.5 GB，首次加载慢属正常，见 FAQ）。
  3. 再加矢量：Add Data 直接选 gapsutm.shp。
  4. 符号化：右键图层 → Symbology → 按 gclass_cn 字段分色 （连片空地 = 橙、株位空缺 = 红、林间空隙 = 黄、不确定 = 灰）； 右键 → Labeling，字段选 gap_id（或 area_sqm）。
  5. 人工核对：右键 → Open Attribute Table，按 area_sqm 降序，从最大块逐块核对。
为什么能自动对齐：shp 的 .prj 声明 WGS_1984 UTM Zone 49N（EPSG:32649，单位米）， TIF 的 WGR17.prj 声明 WGS84（EPSG:4326）。两者不同但都明确， ArcGIS 会自动执行 on-the-fly 动态投影，直接叠在一起——不需要你做任何坐标系操作。
🅱️ 路线 B · ArcGIS Pro 导入 GeoJSON
  1. Map → Add Data，选 gaps-all-utm49n.geojson。
  2. 关键一步：若弹出坐标系选择框，选 Projected Coordinate Systems → UTM → WGS 1984 → UTM Zone 49N。
  3. 若已经加进来且位置不对：右键图层 → Properties → Coordinate Systems 手动指定。
  4. 也可用 Geoprocessing 工具 JSON To Features，输出坐标系显式选择。
⚠️ 若跳过第 2 步（或没有指定坐标系），就会复现「一堆直线」—— 这正是本次诊断出的根因。GeoJSON 方案不是不能用，而是必须手动确认坐标系。
©️ 路线 C · ArcMap 10.x
  • 版本 ≥ 10.5：File → Add Data 直接选 gaps-all-utm49n.geojson，同样注意指定坐标系。
  • 版本 < 10.5：不支持 GeoJSON，必须用 shapefile—— 解压 gaps-all-wgs84-shp.zip 或 by-class/ 下的分类 zip。
  • 或用 Conversion Tools → JSON → JSON To Features，输出坐标系选 WGS84 或 UTM 49N。
🌍 路线 D · 不想开 ArcGIS：双击 KML 用 Google Earth

直接双击 gaps-all.kml 即可。KML 按类别分好文件夹（可勾选显示/隐藏）， 点击每块空地可看到面积、长宽比等属性。KML 规范强制 WGS84，永远正确， 适合快速扫一遍大块空地。

七、FAQ

Q1：为什么 KML 好使，GeoJSON 不好使？
KML 规范强制 lon,lat,alt 且强制 WGS84，没有任何歧义，Google Earth 闭着眼都不会读错； GeoJSON 虽然也有顶层 crs 成员（已声明 EPSG:4326）， 但 ArcGIS 的 GeoJSON 导入器直接忽略它，按未知平面坐标系处理——于是经纬度数值被当作平面 X/Y，跑偏。
Q2：导入时提示 unknown spatial reference 怎么办？
说明当前文件真的没带 CRS 信息。首选换用 shapefile 路线（.prj 必被 ArcGIS 识别）； 如果必须用 GeoJSON，走 JSON To Features 时显式指定输出坐标系为 EPSG:32649 或 EPSG:4326。
Q3：位置大概对，但整体偏移几百米？
多半是中央经线选错带。本地是 UTM 49N，中央经线 111°E； 若误选 48N（中央经线 105°E）或 50N（117°E），同一坐标会被横向平移。 检查：右键图层 → Properties → Coordinate Systems，确认是 WGS_1984_UTM_Zone_49N。
Q4：3.5 GB 的 TIF 加载卡顿怎么办？
先建栅格金字塔：ArcToolbox → Data Management Tools → Raster → Raster Dataset → Build Pyramids and Statistics。只额外生成缩放级别的缓存、不改源数据， 之后缩放和平移会明显流畅。矢量侧（1,048 个多边形）体量很小，不会造成卡顿。
Q5：只想看某一类空地怎么办？
用 by-class/ 下的分类 shapefile：gaps-open_patch-*（380 块连片空地）、 gaps-uncertain-*（318 块）、gaps-vacant_slot-*（180 个）、 gaps-alley_gap-*（170 个）。各自单独成层，可单独开关显示。
